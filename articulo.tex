\begin{abstract}
    El presente artículo detalla el diseño, simulación y construcción física de un brazo manipulador antropomórfico de 3 grados de libertad (GDL) orientado al corte y perfilado láser no-coplanar. El objetivo principal ha sido desarrollar un sistema capaz de seguir trayectorias tridimensionales sobre superficies cilíndricas e irregulares mediante un emisor láser en su efector final, controlado por un microcontrolador ESP32. Se han implementado los modelos de cinemática directa, inversa y Jacobiana para garantizar el posicionamiento espacial en los tres ejes ($X, Y, Z$) y conservar la distancia focal del láser. La estructura física se fabricó en impresión 3D a partir de mallas STL, con un firmware desarrollado en C++. La validación cinemática se realizó mediante simulación virtual en ROS 2 y Gazebo de forma puramente offline.
\end{abstract}

\begin{IEEEkeywords}
Cinemática, brazo robótico, ESP32, C++, ROS 2, simulación virtual.
\end{IEEEkeywords}

\section{Introducción}
En la industria moderna, los brazos robóticos son herramientas fundamentales para tareas de precisión como la soldadura y el corte láser. Comprender la cinemática detrás de estos mecanismos es el primer paso para su control y programación \cite{b1}. Este proyecto busca aplicar los conceptos teóricos de modelado de robots ---tales como matrices de transformación homogénea, representación de orientación y cinemática diferencial--- en un caso de uso práctico. 

Al estructurar el modelo con 3 grados de libertad (GDL) (rotación en la base, elevación en el hombro y elevación en el codo), se simplificó el análisis geométrico sin perder la capacidad de posicionar el efector final en un volumen de trabajo tridimensional. Además, el proyecto utiliza un emisor láser de baja potencia (Clase 1/2) como efector final. A diferencia de procesos de contacto como la soldadura por arco, el láser permite una validación cinemática de ``no-contacto''. Esto simplifica el control al eliminar la necesidad de compensar fuerzas de fricción o colisiones mecánicas directas contra la pieza de trabajo, permitiendo un seguimiento de trayectoria preciso y eficiente. Este enfoque es crucial para el corte y grabado sobre superficies irregulares y curvadas en tres dimensiones, donde el brazo debe seguir contornos tridimensionales curvos sobre una superficie no plana manteniendo constante la distancia focal del haz láser, una operación inviable para máquinas cartesianas 2D tradicionales. El desarrollo del software, simulación, firmware embebido e interfaz web se encuentra disponible de forma pública en el repositorio de GitHub del proyecto \cite{b2}.

\section{Objetivos}
\subsection{Objetivo General}
Desarrollar, simular y construir un brazo robótico articulado de 3 GDL orientado a procesos de corte láser no-coplanar sobre superficies curvas e irregulares, validando los modelos cinemáticos en simulación virtual (ROS 2/Gazebo) y, de forma independiente, en el prototipo físico controlado por un ESP32.

\subsection{Objetivos Específicos}
\begin{itemize}
    \item Definir los parámetros de Denavit-Hartenberg y resolver analíticamente la cinemática directa, inversa y Jacobiana para garantizar el seguimiento espacial tridimensional ($X, Y, Z$) y la evasión de singularidades en superficies no planas.
    \item Modelar la estructura física en URDF/Xacro y simular el comportamiento del sistema utilizando el sistema operativo de robots (ROS 2, por sus siglas en inglés) y Gazebo de manera exclusivamente virtual, sin conexión física con el prototipo.
    \item Fabricar los eslabones y la base del robot utilizando tecnologías de impresión 3D a partir de archivos STL.
    \item Implementar el control de bajo nivel del hardware mediante un microcontrolador ESP32, utilizando C++ para accionar las articulaciones físicas del prototipo.
\end{itemize}

\section{Modelado Cinemático}
Se utiliza la convención de Denavit-Hartenberg (D-H) clásica para describir la geometría y cinemática del brazo manipulador antropomórfico de 3 GDL.

\subsection{Justificación de la Morfología y Comparación de Alternativas}
El brazo robótico desarrollado se destina a la aplicación de corte y perfilado láser no-coplanar sobre piezas cilíndricas. Específicamente, el objetivo es seguir trayectorias espaciales complejas sobre una superficie cilíndrica con un diámetro real de $5.3\text{ cm}$ (radio $R_{\text{tubo}} = 26.5\text{ mm}$) montada sobre un soporte de $60\text{ mm}$ de altura. La pieza cilíndrica está posicionada a una distancia nominal de $x_{\text{tubo}} = 350\text{ mm}$ y una altura de base $z_{\text{tubo}} = 60\text{ mm}$ con respecto al origen de la base del robot. Para esta tarea, es indispensable posicionar el efector final de manera tridimensional ($X, Y, Z$) controlando dinámicamente la altura del cabezal para mantener una distancia de enfoque constante normal al cilindro, evitando colisiones con la estructura del tubo.

Las restricciones físicas del proyecto imponen el uso de actuadores servo de bajo costo (dos MG996R y un MG90S) con un presupuesto de torque limitado. Esto restringe la masa del efector final, lo que justifica la selección de un diodo láser semiconductor ligero de estado sólido ($10\text{ g}$) que no introduce esfuerzos inerciales significativos a diferencia de herramientas de mecanizado por contacto.

Con el fin de justificar la selección de la morfología antropomórfica de 3 GDL (RRR), se analizaron diferentes arquitecturas robóticas estándar de 3 GDL (Tabla~\ref{tab:comparacion_morfologia}).

La morfología antropomórfica RRR resulta idónea para esta aplicación al permitir que el brazo se ``enrosque'' o alcance por encima de la curvatura de la pieza cilíndrica sin que sus eslabones interfieran con ella, manteniendo una alta rigidez en un diseño compacto. Su espacio de trabajo esperado se caracteriza por una envoltura esférica truncada determinada por los límites de las articulaciones físicas del prototipo:
\begin{itemize}
    \item Articulación 1 (Base): $\theta_1 \in [-90^\circ, 90^\circ]$ (debido a la restricción física de $180^\circ$ del servomotor).
    \item Articulación 2 (Hombro): $\theta_2 \in [-90^\circ, 90^\circ]$ (restringido en firmware a $[-10^\circ, 90^\circ]$ por seguridad estructural).
    \item Articulación 3 (Codo): $\theta_3 \in [-90^\circ, 90^\circ]$ (restringido en firmware a $[-120^\circ, 10^\circ]$ para evitar colisión con el plano de soporte).
    \item Alcance radial máximo: $R_{\text{max}} = a_2 + a_3 + a_4 = 322.000\text{ mm}$
\end{itemize}

\subsection{Sistemas de Referencia y Parámetros D-H}
Se definen cuatro sistemas de referencia locales $\{0\}$, $\{1\}$, $\{2\}$ y $\{3\}$ asociados a cada articulación móvil y al efector final de la estructura, coincidiendo con los marcos de simulación.
\begin{itemize}
    \item $d_1 = 60\text{ mm}$: Altura del pedestal de la base.
    \item $d_2 = 36\text{ mm}$: Altura del hombro.
    \item $a_2 = 15\text{ mm}$: Desfase radial base-hombro.
    \item $a_3 = 146\text{ mm}$: Longitud del primer eslabón móvil.
    \item $a_4 = 161\text{ mm}$: Longitud del segundo eslabón móvil.
    \item $d_4 = -7\text{ mm}$: Desplazamiento transversal del efector.
    \item $\theta_1$: Ángulo de rotación de la base (alrededor del eje vertical $Z_0$).
    \item $\theta_2$: Ángulo del hombro.
    \item $\theta_3$: Ángulo del codo.
\end{itemize}

La convención clásica de D-H establece que la matriz de transformación homogénea entre eslabones consecutivos se calcula mediante:
\begin{equation}
T_i^{i-1} = \begin{bmatrix} \cos\theta_i & -\sin\theta_i \cos\alpha_i & \sin\theta_i \sin\alpha_i & a_i \cos\theta_i \\ \sin\theta_i & \cos\theta_i \cos\alpha_i & -\cos\theta_i \sin\alpha_i & a_i \sin\theta_i \\ 0 & \sin\alpha_i & \cos\alpha_i & d_i \\ 0 & 0 & 0 & 1 \end{bmatrix}
\label{eq:dh_matrix}
\end{equation}

A partir de los sistemas de referencia y dimensiones físicas asignados, se obtiene la Tabla de Parámetros D-H (Tabla~\ref{tab:dh_parametros}). La Fig.~\ref{fig:dh_diagram} ilustra la disposición geométrica de estos parámetros sobre el modelo físico del brazo en su configuración de reposo ($\theta_1 = \theta_2 = \theta_3 = 0$).

\subsubsection{Mapeo de Variables Articulares y Desfases Geométricos}
Es fundamental destacar que las variables articulares $\theta_i$ de la Tabla~\ref{tab:dh_parametros} corresponden al modelo teórico de Denavit-Hartenberg (donde el brazo totalmente extendido horizontalmente define los ángulos de hombro y codo $\theta_2 = \theta_3 = 0$). Sin embargo, en la construcción física del prototipo y en el modelo descriptor URDF de ROS 2/Gazebo, los servomotores se calibran en posiciones angulares relativas a sus ejes de montaje estructural. La correspondencia matemática exacta entre los ángulos teóricos de D-H ($\theta_2^*, \theta_3^*$) y los ángulos físicos comandados a los servomotores ($\theta_2, \theta_3$) está definida por los desfasajes angulares mecánicos $\phi_2 \approx 59.017^\circ$ ($1.030041\text{ rad}$) y $\phi_3 \approx -10.966^\circ$ ($-0.191392\text{ rad}$):
\begin{align}
\theta_2^* &= \theta_2 + \phi_2 \\
\theta_3^* &= \theta_3 + \phi_3 - \phi_2
\end{align}
Donde $\theta_2^*$ y $\theta_3^*$ son los ángulos efectivos utilizados en las matrices de transformación homogénea y en el cálculo de cinemática directa analítica, mientras que $\theta_2$ y $\theta_3$ son los ángulos comandados desde el software de control a las articulaciones físicas del robot.

\subsection{Cinemática Directa}
Sustituyendo los parámetros de la Tabla~\ref{tab:dh_parametros} en \eqref{eq:dh_matrix}, se obtienen las matrices de transformación homogénea individuales para cada articulación y eslabón:

\begin{equation}
T_1^0 = \begin{bmatrix} \cos\theta_1 & 0 & \sin\theta_1 & a_2\cos\theta_1 \\ \sin\theta_1 & 0 & -\cos\theta_1 & a_2\sin\theta_1 \\ 0 & 1 & 0 & d_1 + d_2 \\ 0 & 0 & 0 & 1 \end{bmatrix}
\end{equation}

\begin{equation}
T_2^1 = \begin{bmatrix} \cos\theta_2 & -\sin\theta_2 & 0 & a_3\cos\theta_2 \\ \sin\theta_2 & \cos\theta_2 & 0 & a_3\sin\theta_2 \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{bmatrix}
\end{equation}

\begin{equation}
T_3^2 = \begin{bmatrix} \cos\theta_3 & -\sin\theta_3 & 0 & a_4\cos\theta_3 \\ \sin\theta_3 & \cos\theta_3 & 0 & a_4\sin\theta_3 \\ 0 & 0 & 1 & d_4 \\ 0 & 0 & 0 & 1 \end{bmatrix}
\end{equation}

Multiplicando consecutivamente estas matrices se obtiene la matriz de transformación homogénea total del efector final respecto a la base del robot $T_3^0 = T_1^0 T_2^1 T_3^2$. Definimos esta matriz en función de las coordenadas del efector final $[x_E, y_E, z_E]^T$ dadas en \eqref{eq:fk_x}-\eqref{eq:fk_z}:
\begin{equation}
T_3^0 = \begin{bmatrix} C_1 C_{23} & -C_1 S_{23} & S_1 & x_E \\ S_1 C_{23} & -S_1 S_{23} & -C_1 & y_E \\ S_{23} & C_{23} & 0 & z_E \\ 0 & 0 & 0 & 1 \end{bmatrix}
\label{eq:matrix_total}
\end{equation}
donde se utiliza la notación compacta $C_1 = \cos\theta_1$, $S_1 = \sin\theta_1$, $C_{23} = \cos(\theta_2+\theta_3)$ y $S_{23} = \sin(\theta_2+\theta_3)$.

El vector de posición del efector final $P_E = [x_E, y_E, z_E]^T$ está dado por:
\begin{equation}
x_E = \cos\theta_1 \left( a_2 + a_3 \cos\theta_2 + a_4 \cos(\theta_2 + \theta_3) \right) + d_4 \sin\theta_1
\label{eq:fk_x}
\end{equation}
\begin{equation}
y_E = \sin\theta_1 \left( a_2 + a_3 \cos\theta_2 + a_4 \cos(\theta_2 + \theta_3) \right) - d_4 \cos\theta_1
\label{eq:fk_y}
\end{equation}
\begin{equation}
z_E = d_1 + d_2 + a_3 \sin\theta_2 + a_4 \sin(\theta_2 + \theta_3)
\label{eq:fk_z}
\end{equation}

Para verificar la consistencia del modelo matemático desarrollado, se evalúan las ecuaciones de cinemática directa bajo la configuración de reposo del prototipo (con todas las articulaciones en sus posiciones centrales $\theta_1 = 0$, $\theta_2 = 0$, $\theta_3 = 0$). En este estado, al sustituir los valores y las constantes físicas en \eqref{eq:fk_x}-\eqref{eq:fk_z}, se obtiene:
\begin{align}
x_E &= a_2 + a_3 \cos(0) + a_4 \cos(0) \nonumber \\
    &= 15 + 146 + 161 = 322\text{ mm} \\
y_E &= -d_4 = 7\text{ mm} \\
z_E &= d_1 + d_2 + a_3 \sin(0) + a_4 \sin(0) \nonumber \\
    &= 60 + 36 + 0 + 0 = 96\text{ mm}
\end{align}
Estos resultados analíticos coinciden exactamente con las coordenadas de la brida (efector final) obtenidas directamente del árbol de transformadas (TF) de la simulación virtual de ROS 2 ($X = 322\text{ mm}$, $Y = 7\text{ mm}$, $Z = 96\text{ mm}$). Esto valida la precisión del modelo cinemático de 4 sistemas propuesto para el guiado de trayectorias.

Para hallar la distancia total en 3D desde el origen del sistema de referencia $\{0\}$ hasta el efector final en esta posición de reposo, se descompone el cálculo geométrico en dos etapas mediante el teorema de Pitágoras:
1) Primero, se considera la proyección bidimensional sobre el plano longitudinal del brazo (vista lateral, Fig.~\ref{fig:distancia_lateral}), omitiendo temporalmente el desplazamiento transversal $d_4$. En esta vista, el vector de posición proyectado tiene componentes $(x_{\text{plane}}, z_{\text{plane}})$, donde:
\begin{align}
x_{\text{plane}} &= a_2 + a_3 + a_4 = 15 + 146 + 161 = 322\text{ mm} \\
z_{\text{plane}} &= d_1 + d_2 = 60 + 36 = 96\text{ mm}
\end{align}
La distancia proyectada $D_{\text{plane}}$ actúa como la hipotenusa de este primer triángulo rectángulo en el plano vertical:
\begin{equation}
\begin{split}
D_{\text{plane}} &= \sqrt{x_{\text{plane}}^2 + z_{\text{plane}}^2} \\
&= \sqrt{322^2 + 96^2} \\
&= \sqrt{112900} = 336\text{ mm}
\end{split}
\end{equation}
Es de destacar que esta combinación de parámetros físicos produce un valor entero exacto de $336\text{ mm}$ para la hipotenusa del plano de movimiento longitudinal.
2) Segundo, para determinar la distancia tridimensional real, se toma $D_{\text{plane}}$ como el primer cateto y el desfase lateral $d_4 = 7\text{ mm}$ como el segundo cateto de un nuevo triángulo rectángulo en el espacio 3D. La hipotenusa resultante representa la distancia total del efector final al origen:
\begin{equation}
\begin{split}
D_{\text{total}} &= \sqrt{D_{\text{plane}}^2 + d_4^2} \\
&= \sqrt{336^2 + 7^2} \\
&= \sqrt{112949} \approx 336.08\text{ mm}
\end{split}
\end{equation}
Este método valida geométricamente que las coordenadas tridimensionales calculadas mediante el formalismo D-H son consistentes con la morfología del hardware real.

\subsection{Cinemática Inversa y Análisis de Múltiples Soluciones}
La resolución de la cinemática inversa consiste en determinar los ángulos físicos de los servomotores $(\theta_1, \theta_2, \theta_3)$ a partir de una posición cartesiana deseada $P_E = [x_E, y_E, z_E]^T$. Para ello, desacoplamos el efecto de la rotación de la base y del desfase transversal $d_4$ de la siguiente manera:

1) \textit{Cálculo de $\theta_1$ (Rotación de la Base):} 
Geométricamente, definimos el radio proyectado plano $R_p$ como la longitud de la proyección horizontal de los eslabones principales del brazo en el suelo (desde el eje central de rotación de la base hasta la punta del brazo). A partir de la cinemática directa en \eqref{eq:fk_x}-\eqref{eq:fk_y}, este radio está determinado por los eslabones físicos $a_i$ y los ángulos del hombro y codo como:
\begin{equation}
R_p = a_2 + a_3 \cos\theta_2 + a_4 \cos(\theta_2 + \theta_3)
\label{eq:ik_rp_geom}
\end{equation}
Para desacoplar el ángulo de la base $\theta_1$, consideramos la posición de la punta del brazo en el marco de referencia local del brazo $\{1\}$ (el cual gira con la base un ángulo $\theta_1$). En dicho plano local, la coordenada a lo largo del brazo es $x_1 = R_p$ y la coordenada transversal debida al desfase transversal de la herramienta es $y_1 = -d_4$. La transformación de estas coordenadas locales al marco global $\{0\}$ de la base se realiza mediante una matriz de rotación alrededor del eje vertical $Z_0$:
\begin{equation}
\begin{bmatrix} x_E \\ y_E \end{bmatrix} = \begin{bmatrix} \cos\theta_1 & -\sin\theta_1 \\ \sin\theta_1 & \cos\theta_1 \end{bmatrix} \begin{bmatrix} R_p \\ -d_4 \end{bmatrix}
\label{eq:ik_rotacion_base}
\end{equation}
Al resolver el producto de la matriz anterior, obtenemos las ecuaciones de la cinemática directa:
\begin{align}
x_E &= R_p \cos\theta_1 + d_4 \sin\theta_1 \label{eq:ik_proj_x} \\
y_E &= R_p \sin\theta_1 - d_4 \cos\theta_1 \label{eq:ik_proj_y}
\end{align}
Elevando al cuadrado y sumando ambas expresiones, el ángulo $\theta_1$ se elimina mediante la identidad trigonométrica fundamental $\sin^2\theta_1 + \cos^2\theta_1 = 1$, lo que nos permite calcular directamente el valor numérico de $R_p$ a partir de la coordenada cartesiana de consigna $(x_E, y_E)$:
\begin{equation}
x_E^2 + y_E^2 = R_p^2 + d_4^2 \implies R_p = \sqrt{x_E^2 + y_E^2 - d_4^2}
\label{eq:ik_rp}
\end{equation}
Realizando la sustitución de variables polares en el plano $XY$ mediante $x_E = R \cos\beta$ y $y_E = R \sin\beta$ (donde $R = \sqrt{x_E^2 + y_E^2}$ y $\beta = \operatorname{atan2}(y_E, x_E)$), las ecuaciones se transforman en:
\begin{align}
R \cos(\beta - \theta_1) &= R_p \\
R \sin(\beta - \theta_1) &= -d_4
\end{align}
Dividiendo ambas expresiones trigonométricas, obtenemos el ángulo diferencial respecto a la proyección cartesiana:
\begin{equation}
\beta - \theta_1 = \operatorname{atan2}(-d_4, R_p)
\end{equation}
Despejando $\theta_1$, se deriva la solución analítica exacta:
\begin{equation}
\theta_1 = \operatorname{atan2}(y_E, x_E) - \operatorname{atan2}(-d_4, R_p)
\label{eq:ik_theta1}
\end{equation}

2) \textit{Cálculo de $\theta_3$ (Elevación del Codo):}
Se define la proyección en el plano longitudinal del brazo. El radio proyectado corregido $r$ (distancia horizontal desde el eje del hombro al efector) y la altura corregida respecto al hombro $z'$ se formulan como:
\begin{equation}
r = R_p - a_2
\end{equation}
\begin{equation}
z' = z_E - (d_1 + d_2)
\end{equation}
Aplicando la ley de los cosenos en el triángulo formado por los eslabones $a_3$ y $a_4$ en el plano del brazo para resolver el ángulo del codo $\theta_3$:
\begin{equation}
r^2 + z'^2 = a_3^2 + a_4^2 - 2 a_3 a_4 \cos(180^\circ - \theta_3)
\end{equation}
Considerando que $\cos(180^\circ - \theta_3) = -\cos\theta_3$, se tiene:
\begin{equation}
r^2 + z'^2 = a_3^2 + a_4^2 + 2 a_3 a_4 \cos\theta_3
\end{equation}
Despejando el término del coseno se obtiene:
\begin{equation}
\cos\theta_3 = \frac{r^2 + z'^2 - a_3^2 - a_4^2}{2 a_3 a_4} = \Psi
\label{eq:ik_cos3}
\end{equation}
Para la existencia de una solución física real libre de números complejos, se debe cumplir estrictamente $-1 \le \Psi \le 1$. Físicamente, un valor fuera de este rango denota que la coordenada cartesiana solicitada se encuentra fuera del alcance del manipulador (ya sea por estar muy lejana o excesivamente cercana a la base). En lugar de calcular el ángulo directamente mediante la función de arco coseno ($\theta_3 = \arccos\Psi$), la cual presenta inestabilidad numérica en las fronteras ($\Psi \approx \pm 1$) e incertidumbre respecto al signo del ángulo, se recurre al cálculo del seno de $\theta_3$ mediante la identidad trigonométrica fundamental, $\sin\theta_3 = \pm\sqrt{1 - \Psi^2}$. Esto permite resolver el ángulo de forma numéricamente robusta en todo el rango $[-\pi, \pi]$ mediante el operador arcotangente de dos argumentos:
\begin{equation}
\theta_3 = \operatorname{atan2}\left( \pm\sqrt{1 - \Psi^2}, \Psi \right)
\label{eq:ik_theta3}
\end{equation}
donde el signo positivo ($+$) representa la configuración de codo abajo (Elbow Down) y el signo negativo ($-$) representa la de codo arriba (Elbow Up). 

En el firmware del microcontrolador ESP32 y en la interfaz gráfica, se selecciona de forma exclusiva la configuración de codo arriba (utilizando el signo negativo). Esta decisión de diseño mecánico y de control evita colisiones físicas del eslabón distal con la mesa de trabajo o la base de soporte, asegurando un despeje máximo de la herramienta y mejorando la operabilidad en superficies no planas.

3) \textit{Cálculo de $\theta_2$ (Elevación del Hombro):}
Una vez obtenido $\theta_3$, se descompone la posición cartesiana en el plano del brazo:
\begin{align}
r &= a_3 \cos\theta_2 + a_4 \cos(\theta_2 + \theta_3) \\
z' &= a_3 \sin\theta_2 + a_4 \sin(\theta_2 + \theta_3)
\end{align}
Expandiendo las identidades trigonométricas de la suma de ángulos y agrupando los términos:
\begin{align}
r &= (a_3 + a_4 \cos\theta_3) \cos\theta_2 - (a_4 \sin\theta_3) \sin\theta_2 \\
z' &= (a_3 + a_4 \cos\theta_3) \sin\theta_2 + (a_4 \sin\theta_3) \cos\theta_2
\end{align}
Definiendo las constantes auxiliares sintonizadas $k_1 = a_3 + a_4 \cos\theta_3$ y $k_2 = a_4 \sin\theta_3$, se reescribe el sistema lineal como:
\begin{align}
r &= k_1 \cos\theta_2 - k_2 \sin\theta_2 \\
z' &= k_1 \sin\theta_2 + k_2 \cos\theta_2
\end{align}
Resolviendo el sistema algebraico para los términos de $\sin\theta_2$ y $\cos\theta_2$:
\begin{align}
\sin\theta_2 &= \frac{k_1 z' - k_2 r}{k_1^2 + k_2^2} \\
\cos\theta_2 &= \frac{k_1 r + k_2 z'}{k_1^2 + k_2^2}
\end{align}
Dividiendo ambas expresiones se determina de manera única el ángulo de elevación del hombro:
\begin{equation}
\theta_2 = \operatorname{atan2}\left( k_1 z' - k_2 r, k_1 r + k_2 z' \right)
\label{eq:ik_theta2}
\end{equation}

Alternativamente, aplicando el método geométrico directo para un manipulador planar de 2 GDL (con eslabones $a_3$ y $a_4$), el ángulo del hombro $\theta_2$ se formula a partir de la diferencia de ángulos en el triángulo del brazo:
\begin{equation}
\theta_2 = \operatorname{atan2}(z', r) - \operatorname{atan2}(a_4 \sin\theta_3, a_3 + a_4 \cos\theta_3)
\label{eq:ik_theta2_geom}
\end{equation}
La equivalencia matemática entre la solución algebraica \eqref{eq:ik_theta2} y la solución geométrica \eqref{eq:ik_theta2_geom} se demuestra mediante la identidad de la diferencia de arcotangentes, $\operatorname{atan2}(A, B) - \operatorname{atan2}(C, D) = \operatorname{atan2}(A D - B C, B D + A C)$, lo que valida la coherencia cinemática del modelo embebido en el microcontrolador.

\subsubsection{Gestión de Límites Articulares y Puntos Inalcanzables}
Para garantizar la integridad física del manipulador y evitar fallas críticas de ejecución en el resolvedor matemático:
\begin{itemize}
    \item \textbf{Detección de Coordenadas Fuera de Alcance:} El algoritmo evalúa el valor de $\Psi$ en \eqref{eq:ik_cos3} antes de calcular la raíz cuadrada en \eqref{eq:ik_theta3}. Si $|\Psi| > 1.0$, la coordenada solicitada se encuentra geométricamente fuera de la frontera de alcance del robot (muy lejana o muy cercana a la base). En este caso, el software descarta la consigna cartesiana, genera una alerta visual de tipo \texttt{OUT\_OF\_RANGE} y detiene el movimiento del láser. Se aplica una pequeña tolerancia de $\pm 0.005$ para compensar errores de truncamiento decimal de punto flotante en las fronteras extremas del espacio de trabajo.
    \item \textbf{Filtro de Límites Articulares:} Una vez calculada la terna $(\theta_1, \theta_2, \theta_3)$, se comprueba que se cumplan las restricciones físicas de giro de los actuadores del prototipo real (limitados a un rango de operación física de $180^\circ$):
    \begin{align}
    -90^\circ &\le \theta_1 \le 90^\circ \\
    -90^\circ &\le \theta_2 \le 90^\circ \\
    -90^\circ &\le \theta_3 \le 90^\circ
    \end{align}
    Adicionalmente, el firmware del ESP32 restringe de forma más estricta estos márgenes angulares para garantizar la seguridad del hardware frente a sobrecorrientes o colisiones con la mesa de trabajo:
    \begin{align}
    -10^\circ &\le \theta_{2} \le 90^\circ \\
    -120^\circ &\le \theta_{3} \le 10^\circ
    \end{align}
    Cualquier consigna que viole estos límites se descarta automáticamente para evitar colisiones mecánicas directas o sobre-esfuerzo de los servomotores.
\end{itemize}

\subsection{Jacobiano, Singularidades y Caracterización del Espacio de Trabajo}
La cinemática diferencial del manipulador relaciona las velocidades del espacio articular con las velocidades lineales del efector en el espacio cartesiano. Para obtener la matriz Jacobiana $J_v \in \mathbb{R}^{3 \times 3}$, se recurre al método geométrico (productos vectoriales basados en los sistemas de referencia D-H), siendo el más conveniente por su simplicidad en articulaciones rotacionales, expresándose columna por columna como:
\begin{equation}
J_{v_i} = z_{i-1} \times (p_e - p_{i-1})
\end{equation}

Al aplicar esta metodología a nuestro manipulador de 3 GDL, se definen los ejes de rotación en el sistema de referencia global:
\begin{equation}
z_0 = \begin{bmatrix} 0 \\ 0 \\ 1 \end{bmatrix}, \quad z_1 = z_2 = \begin{bmatrix} \sin\theta_1 \\ -\cos\theta_1 \\ 0 \end{bmatrix}
\end{equation}
y los vectores de posición relativos del efector $p_e$ respecto a la base $p_0$ y al codo $p_2$:
\begin{align}
p_e - p_0 &= \begin{bmatrix} R_p \cos\theta_1 + d_4 \sin\theta_1 \\ R_p \sin\theta_1 - d_4 \cos\theta_1 \\ z_e \end{bmatrix} \\
p_e - p_2 &= \begin{bmatrix} a_4 \cos(\theta_2+\theta_3)\cos\theta_1 + d_4\sin\theta_1 \\ a_4\cos(\theta_2+\theta_3)\sin\theta_1 - d_4\cos\theta_1 \\ a_4\sin(\theta_2+\theta_3) \end{bmatrix}
\end{align}
donde $R_p = a_2 + a_3 \cos\theta_2 + a_4 \cos(\theta_2 + \theta_3)$ es el radio proyectado del brazo. Al calcular los productos vectoriales cruzados, se obtienen las columnas de la velocidad lineal:
\begin{equation}
J_{v_1} = z_0 \times (p_e - p_0) = \begin{bmatrix} -R_p \sin\theta_1 + d_4 \cos\theta_1 \\ R_p \cos\theta_1 + d_4 \sin\theta_1 \\ 0 \end{bmatrix}
\end{equation}
\begin{equation}
J_{v_3} = z_2 \times (p_e - p_2) = \begin{bmatrix} -a_4 \cos\theta_1 \sin(\theta_2+\theta_3) \\ -a_4 \sin\theta_1 \sin(\theta_2+\theta_3) \\ a_4 \cos(\theta_2+\theta_3) \end{bmatrix}
\end{equation}
Al agrupar las tres columnas del manipulador, se conforma la matriz Jacobiana lineal final:
\begin{equation}
J_v = \begin{bmatrix} -S_1 R_p + d_4 C_1 & -C_1(a_3 S_2 + a_4 S_{23}) & -C_1 a_4 S_{23} \\ C_1 R_p + d_4 S_1 & -S_1(a_3 S_2 + a_4 S_{23}) & -S_1 a_4 S_{23} \\ 0 & a_3 C_2 + a_4 C_{23} & a_4 C_{23} \end{bmatrix}
\label{eq:jacobian}
\end{equation}
donde se emplea la notación compacta $S_i$, $C_i$, $S_{23}$ y $C_{23}$ para representar los senos y cosenos directos. Esto demuestra de forma analítica que el método geométrico entrega exactamente el mismo resultado que la diferenciación analítica.

\subsubsection{Cálculo Simplificado del Determinante}
El determinante de la matriz Jacobiana $J_v$ es una herramienta analítica clave para determinar las singularidades cinemáticas del robot. Para calcularlo de forma simplificada, se realiza la expansión por cofactores a lo largo de la tercera fila de $J_v$ en \eqref{eq:jacobian}. Dado que esta fila posee un elemento nulo ($J_{31} = 0$), el determinante se reduce a la suma de dos términos:
\begin{equation}
\det(J_v) = -J_{32} ( J_{11} J_{23} - J_{13} J_{21} ) + J_{33} ( J_{11} J_{22} - J_{12} J_{21} )
\label{eq:det_cofactores}
\end{equation}

Este cálculo se puede simplificar sustancialmente mediante tres pasos clave:
\begin{enumerate}
    \item \textbf{Eliminación de la orientación de la base ($\theta_1$):} Al expandir los productos cruzados dentro de los paréntesis de \eqref{eq:det_cofactores}, se factoriza de forma natural el término $\sin^2\theta_1 + \cos^2\theta_1$ (utilizando la notación compacta $S_1^2 + C_1^2$). Por la identidad pitagórica fundamental, este término es igual a $1$, eliminando por completo la influencia de $\theta_1$:
    \begin{align}
    J_{11} J_{23} - J_{13} J_{21} &= a_4 S_{23} R_p \\
    J_{11} J_{22} - J_{12} J_{21} &= (a_3 S_2 + a_4 S_{23}) R_p
    \end{align}
    Esto demuestra analíticamente que la orientación angular de la base no afecta las singularidades de posicionamiento del brazo.

    \item \textbf{Agrupamiento de términos en el plano:} Al sustituir las simplificaciones anteriores y los coeficientes de la tercera fila $J_{32} = a_3 C_2 + a_4 C_{23}$ y $J_{33} = a_4 C_{23}$ en \eqref{eq:det_cofactores}, se cancelan los términos que contienen $a_4^2$, reduciendo la expresión a:
    \begin{equation}
    \det(J_v) = a_3 a_4 R_p ( S_2 C_{23} - C_2 S_{23} )
    \end{equation}
    o de forma equivalente en términos trigonométricos expandidos:
    \begin{equation}
    \begin{split}
    \det(J_v) = {}& a_3 a_4 R_p ( \sin\theta_2 \cos(\theta_2+\theta_3) \\
    & - \cos\theta_2 \sin(\theta_2+\theta_3) )
    \end{split}
    \end{equation}

    \item \textbf{Identidad del seno de la diferencia de ángulos:} Utilizando la conocida identidad trigonométrica $\sin(A - B) = \sin A \cos B - \cos A \sin B$ (donde definimos $A = \theta_2$ y $B = \theta_2 + \theta_3$, de modo que $A - B = -\theta_3$ y $\sin(-\theta_3) = -\sin\theta_3$), se llega de forma directa a la formulación final compacta del determinante:
    \begin{equation}
    \det(J_v) = -a_3 a_4 R_p \sin\theta_3
    \label{eq:det_jacobian}
    \end{equation}
\end{enumerate}
Esta expresión demuestra que el determinante es independiente del desfase transversal $d_4$, lo que significa que el descentramiento lateral de la herramienta no influye en las condiciones de bloqueo del brazo.

\subsubsection{Cinemática Diferencial Inversa y Aplicación Numérica}
Para controlar la velocidad de avance del cabezal láser a lo largo del contorno y mantener un haz de corte homogéneo, se calcula la cinemática diferencial inversa, la cual relaciona la velocidad cartesiana lineal de consigna $\dot{P} = [\dot{x}, \dot{y}, \dot{z}]^T$ con las velocidades angulares requeridas en las articulaciones $\dot{q} = [\dot{\theta}_1, \dot{\theta}_2, \dot{\theta}_3]^T$ a través de $\dot{q} = J_v^{-1} \dot{P}$.

Debido a que el determinante de $J_v$ se dedujo en \eqref{eq:det_jacobian}, es posible invertir la matriz de forma analítica desacoplando el movimiento en el plano radial y transversal. Al proyectar la velocidad cartesiana sobre el marco giratorio de la base, la velocidad angular de la base y la tasa de cambio del radio proyectado se expresan como:
\begin{align}
\dot{\theta}_1 &= \frac{- \dot{x} \sin\theta_1 + \dot{y} \cos\theta_1}{R_p} \label{eq:inv_j1} \\
\dot{R}_p &= \dot{x} \cos\theta_1 + \dot{y} \sin\theta_1 - d_4 \dot{\theta}_1 \label{eq:inv_rp}
\end{align}
Con el valor de $\dot{R}_p$ y la velocidad vertical deseada $\dot{z}$, se resuelve el sistema coplanar para el hombro y el codo empleando la inversa de la submatriz planar $J_{\text{planar}}$:
\begin{align}
\dot{\theta}_2 &= \frac{a_4' C_{23} \dot{R}_p + a_4' S_{23} \dot{z}}{a_3 a_4' S_3} \label{eq:inv_j2} \\
\dot{\theta}_3 &= \frac{-(a_3 C_2 + a_4' C_{23}) \dot{R}_p - (a_3 S_2 + a_4' S_{23}) \dot{z}}{a_3 a_4' S_3} \label{eq:inv_j3}
\end{align}
donde se emplea la notación compacta $S_3 = \sin\theta_3$, $C_2 = \cos\theta_2$, $S_2 = \sin\theta_2$, $C_{23} = \cos(\theta_2+\theta_3)$ y $S_{23} = \sin(\theta_2+\theta_3)$.

A modo de verificación práctica de estas ecuaciones de velocidad, se evalúa numéricamente el comportamiento dinámico del manipulador real con el eslabón extendido del láser $a_4' = 361\text{ mm}$ en la configuración articular $\theta_1 = 0$, $\theta_2 = 30^\circ$ ($0.5236\text{ rad}$) y $\theta_3 = -45^\circ$ ($-0.7854\text{ rad}$), asumiendo un requerimiento de velocidad lineal pura en sentido transversal (eje $Y$) de $\dot{P} = [0, 100, 0]^T\text{ mm/s}$ (equivalente a un barrido transversal de $10\text{ cm/s}$ sobre la pieza):

1) \textit{Cálculo del radio proyectado $R_p$:}
\begin{align*}
R_p &= a_2 + a_3 \cos\theta_2 + a_4' \cos(\theta_2+\theta_3) \\
    &= 15 + 146 \cos(30^\circ) + 361 \cos(-15^\circ) \\
    &\approx 15 + 126.44 + 348.69 = 490.13\text{ mm}
\end{align*}

2) \textit{Determinación de las velocidades articulares:}
\begin{itemize}
    \item Sustituyendo en \eqref{eq:inv_j1} con $\sin(0) = 0$ y $\cos(0) = 1$:
    \begin{equation*}
    \dot{\theta}_1 = \frac{-0 \cdot 0 + 100 \cdot 1}{490.13} \approx 0.2040\text{ rad/s} \quad (\approx 11.69^\circ\text{/s})
    \end{equation*}
    \item A partir del valor de $\dot{\theta}_1$, calculamos $\dot{R}_p$ mediante \eqref{eq:inv_rp}:
    \begin{equation*}
    \dot{R}_p = 0 \cdot 1 + 100 \cdot 0 - (-7) \cdot 0.2040 \approx 1.428\text{ mm/s}
    \end{equation*}
    \item Con $\dot{R}_p = 1.428\text{ mm/s}$ y $\dot{z} = 0$, resolvemos las velocidades angulares del hombro y del codo a través de \eqref{eq:inv_j2} y \eqref{eq:inv_j3}:
    \begin{align*}
    \dot{\theta}_2 &= \frac{361 \cos(-15^\circ) \cdot 1.428 + 0}{146 \cdot 361 \sin(-45^\circ)} \\
                   &= \frac{497.93}{-37267.4} \approx -0.0134\text{ rad/s} \quad (\approx -0.77^\circ\text{/s}) \\
    \dot{\theta}_3 &= \frac{-(146 \cos(30^\circ) + 361 \cos(-15^\circ)) \cdot 1.428 - 0}{146 \cdot 361 \sin(-45^\circ)} \\
                   &= \frac{-678.53}{-37267.4} \approx 0.0182\text{ rad/s} \quad (\approx 1.04^\circ\text{/s})
    \end{align*}
\end{itemize}
Este cálculo demuestra cómo se distribuye vectorialmente la velocidad de consigna cartesiana en las juntas mecánicas, permitiendo que el software en la computadora host controle la dinámica del movimiento sin saturar el torque de los servomotores físicos.

\subsubsection{Análisis Físico de Singularidades}
Las singularidades cinemáticas son configuraciones o "posturas" específicas donde el robot se bloquea y pierde la capacidad de moverse en alguna dirección del espacio. Matemáticamente ocurren cuando $\det(J_v) = 0$, lo que provoca que el sistema exija velocidades infinitas en los servomotores para realizar movimientos cartesianos mínimos, generando sobrecorrientes y fallos. En este manipulador se identifican dos singularidades críticas:
\begin{itemize}
    \item \textbf{Singularidad del Codo ($\sin\theta_3 = 0 \implies \theta_3 = 0$ ó $\theta_3 = -\pi$):} Ocurre cuando el brazo está completamente estirado o totalmente encogido. En esta posición, el efector no puede realizar ningún movimiento en la dirección radial del brazo (no puede estirarse ni encogerse más). Si se le ordena avanzar en esa dirección, los servomotores del hombro y del codo tendrían que moverse a una velocidad teóricamente infinita para obedecer la consigna, lo que en la práctica produce un bloqueo mecánico del brazo, picos extremos de corriente eléctrica que pueden dañar los motores y el reinicio del microcontrolador ESP32 debido a la sobrecarga.
    \item \textbf{Singularidad de la Base ($R_p = 0$):} Ocurre cuando el codo se repliega de tal manera que el efector final queda alineado exactamente sobre el eje vertical de rotación de la base ($Z_0$). En esta pose, si se le ordena al láser un movimiento horizontal perpendicular al brazo, la base tendría que girar instantáneamente un ángulo de $90^\circ$ (velocidad de giro teóricamente infinita, $\dot{\theta}_1 \to \infty$). Esto genera fuertes oscilaciones, vibraciones inestables y la pérdida del control de posicionamiento en el prototipo físico.
\end{itemize}

La Fig.~\ref{fig:workspace} representa la sección transversal de la envolvente de trabajo en el plano vertical ($R_p$--$Z$).

\subsection{Generación de Trayectorias y Planificación en el Espacio Cartesiano}
Para garantizar la calidad y precisión del corte láser, se implementa una planificación en el espacio cartesiano. La trayectoria requerida sobre la pieza cilíndrica se discretiza en una secuencia ordenada de puntos tridimensionales. Para cada punto de esta secuencia, la computadora host calcula la solución exacta del modelo de cinemática inversa y transmite los ángulos de articulación resultantes al microcontrolador ESP32 a una frecuencia constante de $20\text{ Hz}$.

El algoritmo de planificación proyecta cada píxel del dibujo 2D $(p_x, p_y)$ en una imagen de dimensiones $W_u \times H_u$ a una coordenada cartesiana tridimensional sobre la superficie del cilindro $(x_s, y_s, z_s)$ usando el mapeo inverso:
\begin{align}
x_s &= X_c - R_c \cos\theta \label{eq:map_xs} \\
y_s &= Y_c - \left( \frac{p_x}{W_u - 1} - 0.5 \right) \cdot W_{\text{flat}} \label{eq:map_ys} \\
z_s &= Z_c + R_c \sin\theta \label{eq:map_zs}
\end{align}
donde $X_c = 500\text{ mm}$, $Y_c = 0\text{ mm}$, $Z_c = 55\text{ mm}$ es la posición central del cilindro, $R_c = 15\text{ mm}$ es su radio, $W_{\text{flat}} = 60\text{ mm}$ es el ancho plano extendido y $\theta = \theta_{\text{max}} - \frac{p_y}{H_u - 1} \cdot 2\theta_{\text{max}}$ (con $\theta_{\text{max}} = 1.25\text{ rad}$) representa la rotación angular del envoltorio.

Para que el haz láser corte de manera efectiva, el efector final físico (punto de salida del haz en la brida) debe situarse a una distancia focal constante de $d_f = 200\text{ mm}$ respecto a la superficie del cilindro. Para implementar esta restricción sin agregar complejidad geométrica al resolvedor de cinemática inversa, se aplica una compensación virtual del largo del eslabón terminal en el resolvedor IK. En lugar de resolver la cinemática inversa con la longitud física del tercer eslabón $a_4 = 161\text{ mm}$, el resolvedor utiliza un eslabón ficticio extendido:
\begin{equation}
a_4' = a_4 + d_f = 161 + 200 = 361\text{ mm}
\label{eq:focal_comp}
\end{equation}
Al ingresar las coordenadas de superficie $(x_s, y_s, z_s)$ como objetivo en la cinemática inversa usando $a_4'$, la junta del codo se posiciona de tal forma que la brida física se sitúa exactamente a $200\text{ mm}$ normales de la superficie del cilindro, manteniendo constante el enfoque del láser durante todo el movimiento.

A modo de ejemplo numérico de aplicación del algoritmo de planificación de trayectorias, se realiza el cálculo completo para un punto de consigna ubicado en el centro de la imagen de entrada ($p_x = 100$, $p_y = 100$) en una cuadrícula de $200 \times 200$ píxeles ($W_u = 200$, $H_u = 200$):

1) \textit{Cálculo de la coordenada angular $\theta$ sobre el cilindro:}
\begin{equation*}
\theta = 1.25 - \frac{100}{199} \cdot 2.50 \approx -0.0063\text{ rad}
\end{equation*}

2) \textit{Mapeo a coordenadas cartesianas 3D sobre la superficie mediante \eqref{eq:map_xs}-\eqref{eq:map_zs}:}
\begin{align*}
x_s &= 500 - 15 \cos(-0.0063) \approx 485.00\text{ mm} \\
y_s &= 0 - \left( \frac{100}{199} - 0.5 \right) \cdot 60 \approx -0.15\text{ mm} \\
z_s &= 55 + 15 \sin(-0.0063) \approx 54.91\text{ mm}
\end{align*}

3) \textit{Compensación focal y resolución de la cinemática inversa:}

\noindent $\bullet$ \textbf{Radio proyectado en la base $R_p$:} Usando el eslabón extendido $a_4' = 361\text{ mm}$, calculamos el radio proyectado $R_p$:
\begin{align*}
r_s &= \sqrt{x_s^2 + y_s^2} \\
&= \sqrt{485.00^2 + (-0.15)^2} \approx 485.00\text{ mm} \\
R_p &= \sqrt{r_s^2 - d_4^2} \\
&= \sqrt{485.00^2 - (-7)^2} \approx 484.95\text{ mm}
\end{align*}

\noindent $\bullet$ \textbf{Ángulo de la articulación de la base $\theta_1$:}
\begin{align*}
\theta_1 &= \operatorname{atan2}(-0.15, 485) - \operatorname{atan2}(7, 484.95) \\
&\approx -0.0147\text{ rad} \quad (\approx -0.84^\circ)
\end{align*}

\noindent $\bullet$ \textbf{Variables coplanares corregidas respecto al hombro:}
\begin{align*}
x_c &= R_p - a_2 = 484.95 - 15 = 469.95\text{ mm} \\
z_c &= z_s - (d_1 + d_2) = 54.91 - 96 = -41.09\text{ mm}
\end{align*}

\noindent $\bullet$ \textbf{Ángulo de la articulación del codo $\theta_3$ (configuración codo-arriba):}
\begin{align*}
\Psi &= \frac{469.95^2 + (-41.09)^2 - 146^2 - 361^2}{2 \cdot 146 \cdot 361} \\
&\approx 0.6724 \\
\theta_3 &= \operatorname{atan2}\left( -\sqrt{1 - 0.6724^2}, 0.6724 \right) \\
&\approx -0.8335\text{ rad} \quad (\approx -47.76^\circ)
\end{align*}

\noindent $\bullet$ \textbf{Ángulo de la articulación del hombro $\theta_2$:}
\begin{align*}
k_1 &= a_3 + a_4' \cos\theta_3 \\
&= 146 + 361(0.6724) \approx 388.74\text{ mm} \\
k_2 &= a_4' \sin\theta_3 \\
&= 361\sin(-0.8335) \approx -267.22\text{ mm} \\
\theta_2 &= \operatorname{atan2}(k_1 z_c - k_2 x_c, k_1 x_c + k_2 z_c) \\
&\approx 0.5147\text{ rad} \quad (\approx 29.49^\circ)
\end{align*}
El resolvedor cartesiano ejecuta estas operaciones para cada punto de la trayectoria en la laptop de forma instantánea y sin experimentar ningún retraso en los cálculos, transmitiendo de manera determinista los ángulos articulares al microcontrolador mediante conexión serie.

A continuación, se detalla el funcionamiento de cada uno de los bloques y su integración en el sistema físico real:

\subsection{Referencias Externas (Trazo Rojo Manual 2D)}
Este bloque representa la consigna de entrada o la trayectoria de referencia deseada en el espacio de la tarea. En el sistema desarrollado, si bien en el entorno de simulación virtual se cargaban letras o vectores predefinidos, en la realidad la referencia consiste en un trazo continuo dibujado a mano alzada con un rotulador de color \textbf{Rojo} directamente sobre la superficie cilíndrica de trabajo. El brazo robótico debe detectar y seguir físicamente este contorno dibujado, permitiendo una interacción directa y guiada por el trazo real en la pieza física.

\subsection{Tareas (Segmentación Trazo Rojo y Esqueletización Zhang-Suen)}
Es la primera etapa de procesamiento de software ejecutada en la computadora host (laptop). Su objetivo es procesar la información de imagen capturada por la cámara USB cenital y extraer de forma determinista la trayectoria geométrica ordenada del trazo físico. Inicialmente, el sistema realiza una mascarilla cian sobre la imagen para aislar y modelar la posición tridimensional del cilindro físico (cuyo cuerpo es de color cian). Posteriormente, para la tarea de guiado de corte, el software segmenta específicamente el \textbf{Trazo Rojo} manual aplicando una máscara de color en el espacio HSV con rangos duales de tono (para cubrir la transición de rojo en los extremos $0^\circ$--$10^\circ$ y $165^\circ$--$180^\circ$).

Sobre esta máscara binaria limpia del trazo rojo, se ejecuta el algoritmo de esqueletización de Zhang-Suen para reducir las líneas a un espesor uniforme de un único píxel. Finalmente, la trayectoria se ordena utilizando el algoritmo del vecino más cercano y se simplifica mediante aproximación poligonal RDP para evitar movimientos discretos bruscos en los actuadores.

\subsection{Generador de Trayectorias (Mapeo 3D y Cinemática Inversa)}
Constituye el resolvedor cinemático y de trayectoria principal, operando en tiempo real en la computadora host a una frecuencia constante de $20\text{ Hz}$. Este bloque recibe la ruta de píxeles secuenciada y realiza las siguientes operaciones consecutivas en la CPU de la laptop:
\begin{enumerate}
    \item Proyección espacial sobre el cilindro mediante las ecuaciones de mapeo inverso \eqref{eq:map_xs}-\eqref{eq:map_zs}, transformando las coordenadas de píxeles $(p_x, p_y)$ a coordenadas cartesianas tridimensionales reales $(x_s, y_s, z_s)$ en milímetros sobre la superficie curva.
    \item Aplicación de la compensación de la distancia de enfoque, la cual utiliza el eslabón extendido virtual $a_4' = a_4 + d_f = 361\text{ mm}$ de \eqref{eq:focal_comp} en lugar de la longitud física de la brida ($a_4 = 161\text{ mm}$), forzando mecánicamente al cabezal del láser a permanecer a una distancia focal constante de $200\text{ mm}$ perpendicular a la superficie cilíndrica.
    \item Resolución del resolvedor cinemático inverso analítico codo-arriba para cada punto de la trayectoria 3D, produciendo la secuencia de ángulos articulares $(\theta_1, \theta_2, \theta_3)$ que se transmiten de manera determinista al hardware a través de la conexión serial.
\end{enumerate}
El resolvedor cartesiano ejecuta estas operaciones en la CPU del host de forma síncrona, eliminando los retrasos de cálculo en el lazo.

\subsection{Control (Microcontrolador ESP32)}
Este bloque representa el controlador digital de bajo nivel de hardware embebido en el microcontrolador físico ESP32. Su función principal es recibir las posiciones articulares $(\theta_1, \theta_2, \theta_3)$ en radianes provenientes del host, validar que cumplan estrictamente con las restricciones de límites angulares físicos para evitar colisiones estructurales, y convertirlas a anchos de pulso de microsegundos de la señal PWM para accionar los servomotores físicos. La recepción se implementa a través de la interfaz UART a 115200 bps mediante tramas de texto estructuradas.

Adicionalmente, el controlador ejecuta tres rutinas críticas en su bucle periódico:
\begin{itemize}
    \item \textbf{Aceleración moveToTarget():} Un algoritmo de interpolación lineal síncrono que divide los cambios angulares repentinos en incrementos máximos de $15\,\mu\text{s}$ ($\approx 1.35^\circ$) espaciados por retardos temporales fijos de $15\text{ ms}$, eliminando los picos de corriente instantáneos en la fuente de alimentación externa que provocan caídas de tensión y el apagado del microcontrolador.
    \item \textbf{Conmutación Síncrona del Láser:} Gestiona de manera coordinada el pin digital GPIO 25 para encender y apagar el haz de luz coherente de forma sincronizada con el perfil cinemático de movimiento, previniendo marcas quemadas accidentales en fases de reposo.
    \item \textbf{Watchdog de Seguridad:} Un temporizador por software que comprueba la llegada periódica de comandos seriales. Si transcurren más de $1000\text{ ms}$ sin recibir comandos válidos del host, el microcontrolador desactiva inmediatamente el láser digital para prevenir quemaduras incidentales o incendios en la pieza de trabajo por pérdida de conexión.
\end{itemize}

\subsection{Robot (Mecanismo)}
Consiste en la planta física y mecánica del brazo manipulador antropomórfico de 3 GDL. Está estructurado por la base giratoria y los eslabones articulados fabricados en impresión 3D FDM utilizando plástico PETG de alta rigidez, los tres servomotores que actúan sobre las juntas activas (un MG996R en la base, un MG996R en el hombro y un MG90S en el codo) y el emisor de diodo láser montado en la brida final. Este bloque ejecuta mecánicamente los comandos angulares de junta transformando las señales eléctricas de PWM en torques de eje que desplazan angularmente los eslabones, posicionando espacialmente el emisor y proyectando el haz de luz sobre el entorno cilíndrico.

\subsection{Entorno Externo (Pieza Cilíndrica de Trabajo)}
Es el plano y volumen físico sobre el cual interacciona la herramienta final del robot. En este sistema de estudio, el entorno consiste en un tubo cilíndrico de radio real $R_{\text{tubo}} = 26.5\text{ mm}$ (diámetro $5.3\text{ cm}$) montado sobre un soporte horizontal con una altura de base de $60\text{ mm}$ y situado a una distancia radial fija de $x_{\text{tubo}} = 350\text{ mm}$ con respecto al origen de la base del brazo. La superficie del tubo cilíndrico es la que recibe la proyección de la trayectoria y experimenta la alteración física (grabado o corte térmico) provocada por la colisión del haz de luz láser enfocado. Su geometría introduce una variación no lineal de altura en función del radio de giro.

\subsection{Sensores Exteroceptivos (Cámara USB Cenital)}
Este bloque de sensores proporciona el lazo de realimentación visual externo. Una cámara USB física externa está montada de forma rígida a una distancia fija de $X = 150\text{ mm}$ y una altura de $Z = 25\text{ mm}$ con respecto a la base del robot. La cámara captura continuamente la escena física (el cilindro y el trazo dibujado) y transmite la señal de video (RGB de 640x480 píxeles a 30 fps) a la laptop host. El software utiliza este feed de video óptico cenital para cerrar el lazo, permitiendo la auto-detección del color cian de la pieza cilíndrica, el cálculo de la homografía y la proyección inversa de dibujo plano sobre el contorno físico curvo en tiempo real, compensando cualquier error de alineación estructural.

\subsection{Sensores Interoceptivos (Potenciómetros de Servomotores)}
Constituyen el lazo de realimentación interno de posición de las articulaciones del manipulador. Cada servomotor físico (MG996R y MG90S) cuenta en su interior con un potenciómetro analógico de precisión montado solidariamente al eje de salida de los engranajes reductores y un controlador de control local analógico integrado. El potenciómetro lee constantemente el ángulo de giro real de la junta mecánica y el circuito comparador del servo ajusta instantáneamente la tensión del motor de corriente continua para anular la diferencia respecto a la señal de referencia PWM comandada por el ESP32. Esta realimentación ocurre internamente en cada servomotor a una frecuencia de aproximadamente 1 kHz, garantizando un posicionamiento articular preciso frente a torques de gravedad y fuerzas dinámicas externas sin sobrecargar el procesador del ESP32.



\section{Metodología y Alcance}
La ejecución del proyecto se estructuró en dos fases metodológicas consecutivas:

\subsection{Fase 1: Modelado Mecánico y Simulación Virtual}
Se diseñaron las piezas tridimensionales del manipulador en CAD. Los modelos tridimensionales de los eslabones se exportaron en formato STL para el proceso de manufactura, y se compilaron en un archivo descriptor URDF (con formato de mallas colisionables e inerciales). En el entorno de ROS 2 y Gazebo, se programó un nodo de simulación independiente para validar computacionalmente los modelos de cinemática directa e inversa, garantizando que el seguimiento de las trayectorias cartesianas de corte ocurra libre de colisiones mecánicas directas o singularidades. Esta simulación en ROS 2 y Gazebo se mantiene de forma puramente virtual, sin establecer conexiones directas de comunicación o control hacia el prototipo físico.

\subsection{Fase 2: Fabricación e Integración de Hardware}
La estructura mecánica se fabricó mediante impresión 3D FDM de los archivos STL utilizando plástico PETG con un patrón de relleno de alta densidad (40\% o superior) para absorber esfuerzos de flexión. Se integraron los actuadores en sus correspondientes articulaciones físicas: un servomotor MG996R en la base (giro izquierdo/derecha), un servomotor MG996R en el hombro (para soportar el torque gravitacional) y un servomotor MG90S en el codo.


\section{Implementación de Software y Algoritmos de Control}
El ecosistema de software del manipulador se divide en tres capas fundamentales que operan coordinadamente de forma puramente virtual para el entorno de simulación (la interfaz web interactiva de usuario, el generador síncrono de trayectorias en ROS 2 y el puente de comunicación de red):

\subsection{Arquitectura de Comunicación e Intercambio de Datos}
El ecosistema de software opera en un esquema coordinado donde la interfaz de usuario interactiva y el resolvedor dinámico de la simulación física se comunican en tiempo real a través de un puente HTTP y tópicos de ROS 2. El flujo de datos e integración de los componentes clave se describe a continuación:
\begin{itemize}
    \item \textbf{Capa de Interfaz Gráfica (Frontend):} Implementada en HTML/JS (\texttt{app.js}), captura la interacción del operador mediante barras de desplazamiento para los ángulos articulares o entradas cartesianas tridimensionales de posición ($X, Y, Z$) calculadas localmente mediante cinemática inversa. Cuando ocurre un cambio, la función \texttt{sendJointsToROS()} serializa los ángulos de las articulaciones $J_1, J_2, J_3$ (en grados sexagesimales) dentro de un objeto JSON y realiza una petición HTTP POST throttleada (con un intervalo mínimo de $50\text{ ms}$) hacia el endpoint local de la API \texttt{/api/move}.
    \item \textbf{Capa del Puente de Red (Web Bridge):} El script en Python \texttt{web\_bridge.py} inicializa de forma concurrente un servidor HTTP en el puerto $8080$ y un nodo de ROS 2. Al recibir la petición POST en la ruta \texttt{/api/move}, el manejador de peticiones del servidor decodifica el objeto JSON, recupera los valores angulares y ejecuta la función \texttt{publish\_joints()} del nodo. Esta función convierte de forma instantánea las variables articulares de grados sexagesimales a radianes y las publica en el tópico \texttt{/arm\_controller/commands} de ROS 2.
    \item \textbf{Capa de Simulación Virtual (ROS 2 / Gazebo):} El resolvedor físico y dinámico de Gazebo está suscrito de forma nativa a \texttt{/arm\_controller/commands}. Al recibir los radianes de consigna, los controladores de posición articulares virtuales aplican torques proporcionales para llevar los eslabones simulados del robot a la pose deseada.
    \item \textbf{Generación de Trayectorias Autónomas:} De manera paralela e independiente de la interfaz gráfica, el script \texttt{trajectory\_generator.py} publica directamente en el tópico \texttt{/arm\_controller/commands} a una frecuencia de $50\text{ Hz}$. Este nodo interpola entre una secuencia programada de keyframes utilizando un perfil de velocidad cosenoidal (S-curve), permitiendo realizar validaciones dinámicas automáticas dentro del simulador físico Gazebo de forma desacoplada del frontend web.
\end{itemize}

\subsection{Interfaz Web de Control e Interacción Dinámica (app.js)}
La interfaz de usuario está desarrollada en JavaScript de cliente puro y HTML5. Permite realizar simulación en línea y resolvedor de cinemática inversa interactiva. El algoritmo detallado de la cinemática inversa se presenta en el Código~\ref{lst:ik_js} en el Apéndice~\ref{ap:app_js}.
Los componentes de la capa de interfaz web realizan las siguientes tareas:
\begin{itemize}
    \item \textbf{Lienzo de Dibujo Interactivo (Canvas):} La rutina \texttt{drawRobot()} proyecta en tiempo real el comportamiento dinámico bidimensional del robot sobre un lienzo Canvas HTML5, mostrando vistas superior ($X$-$Y$) y lateral ($X$-$Z$) para dar retroalimentación visual al operador sobre la trayectoria de corte.
    \item \textbf{Interpolación de Suavizado de Movimiento:} Para transicionar sin saltos discretos hacia las coordenadas indicadas, la función \texttt{animateToJoints()} aplica un algoritmo de facilidad cúbica (\textit{Cubic Ease-Out}) a $60\text{ cuadros por segundo}$, emulando el amortiguamiento físico de los servomotores reales.
\end{itemize}

\subsection{Generador de Trayectorias de Simulación (trajectory\_generator.py)}
El nodo generador de trayectorias en Python modela el perfil cinemático de interpolación de simulación en ROS 2 y Gazebo. El lazo periódico de control temporal de este script se detalla en el Código~\ref{lst:traj_py} en el Apéndice~\ref{ap:traj_py}.
Este nodo realiza la generación y control síncrono mediante:
\begin{itemize}
    \item \textbf{Interpolación Cosenoidal (S-curve):} La ecuación cosenoidal suaviza el incremento de velocidad al inicio y finalización del movimiento de cada eslabón, eliminando las aceleraciones abruptas que provocan oscilaciones inerciales o colisiones mecánicas virtuales en el resolvedor de física de Gazebo.
    \item \textbf{Bucle Síncrono a $50\text{ Hz}$:} Garantiza una comunicación continua hacia los controladores articulares virtuales a intervalos exactos de $20\text{ ms}$.
\end{itemize}

\subsection{Puente de Comunicación ROS 2 y Control de Hardware (web\_bridge.py)}
La comunicación intermedia entre la simulación virtual, la interfaz web y el prototipo físico se centraliza en un script multi-hilo desarrollado en Python. Este puente no solo traduce y publica tramas en ROS 2 para Gazebo, sino que integra el control del hardware físico real mediante las siguientes bases técnicas:
\begin{itemize}
    \item \textbf{Servidor HTTP Multihilo y Endpoints de Hardware:} Inicializa un servidor HTTP en el puerto 8080. Para controlar el prototipo real, expone los endpoints \texttt{/api/}\allowbreak\texttt{physical/}\allowbreak\texttt{connect} (conexión UART a 115200 bps), \texttt{/api/}\allowbreak\texttt{physical/}\allowbreak\texttt{move} (envío síncrono de comandos a los servomotores), \texttt{/api/}\allowbreak\texttt{physical/}\allowbreak\texttt{list\_ports} (listado y detección automática de puertos \texttt{/dev/}\allowbreak\texttt{ttyUSB*} / \texttt{/dev/}\allowbreak\texttt{ttyACM*}) y \texttt{/api/}\allowbreak\texttt{physical/}\allowbreak\texttt{status} (estado de conexión y respuesta del firmware).
    \item \textbf{SerialManager Thread-safe:} Implementa una clase de gestión serial con bloqueos de exclusión mutua (\texttt{threading.Lock}). Esto previene condiciones de carrera cuando se envían tramas síncronas periódicas a la planta física. El puente autodetecta el ESP32 a partir de identificadores VID/PID de conversores USB-TTL típicos (CH340, CP210x) y ofrece reconexión dinámica transparente.
    \item \textbf{Servicios y Streaming de Video en Tiempo Real:} Expone el endpoint \texttt{/api/}\allowbreak\texttt{list\_cameras} que escanea y enumera los dispositivos de video ópticos conectados. Además, mediante \texttt{/api/}\allowbreak\texttt{real\_}\allowbreak\texttt{camera\_}\allowbreak\texttt{stream}, sirve un flujo de video cenital en formato multipart/x-mixed-replace (MJPEG) con tasa constante de 16 FPS. Si la cámara real (priorizando \texttt{/dev/}\allowbreak\texttt{video2}) se desconecta físicamente, el endpoint dibuja dinámicamente un fotograma de error y entra en bucle de reintento automático sin colapsar el hilo servidor.
\end{itemize}

\subsection{Procesamiento de Imagen, HSV Red Mask y Trayectoria 3D (web\_bridge.py)}
Para permitir que el brazo robótico físico siga trazos hechos a mano alzada en el mundo real, se diseñó un pipeline de visión artificial y reconstrucción tridimensional:
\begin{itemize}
    \item \textbf{Detección y Homografía del Cilindro:} Utilizando OpenCV, se aísla el cuerpo del cilindro de PETG mediante un filtrado por color en el espacio HSV con una mascarilla cian (rango $[75, 30, 30]$ a $[140, 255, 255]$). Se calcula su caja delimitadora rectangular para proyectar inversamente y desenrollar geométricamente el cilindro físico en un plano de visualización ($W_u \times H_u = 512 \times 256$ píxeles).
    \item \textbf{Segmentación del Trazo Rojo y Zhang-Suen:} Una vez desenrollada la superficie, se extrae el trazo dibujado a mano. Para ello, se aplica una mascarilla de color **Rojo** en el espacio HSV utilizando una unión de rangos duales para abarcar la naturaleza periódica del matiz (Hue): de $[0, 50, 40]$ a $[10, 255, 255]$ (límites inferiores) y de $[165, 50, 40]$ a $[180, 255, 255]$ (límites superiores). La máscara resultante se erosiona para remover ruido de bordes y se procesa mediante el algoritmo vectorizado de Zhang-Suen para reducir el trazo a un espesor unitario manteniendo la topología original.
    \item \textbf{Reconstrucción y Conversión Espacial 3D:} Los píxeles del esqueleto del trazo rojo se ordenan por vecindad y se simplifican mediante Ramer-Douglas-Peucker (RDP). Finalmente, cada píxel $(p_x, p_y)$ se proyecta a coordenadas tridimensionales en milímetros sobre la superficie curva real mediante el mapeo inverso cilíndrico, agregando el estado de conmutación del emisor láser.
\end{itemize}

\subsection{Orquestación y Lanzamiento de Simulación (gazebo.launch.py)}
La configuración y el inicio coordinado de los nodos de simulación física en ROS 2 se gestionan mediante un archivo de lanzamiento desarrollado en Python. El flujo secuencial y la configuración del entorno se detallan en el Código~\ref{lst:launch_py} en el Apéndice~\ref{ap:launch_py}.
Este orquestador realiza las siguientes operaciones:
\begin{itemize}
    \item \textbf{Carga y Procesamiento Dinámico de URDF/Xacro:} El script utiliza la utilidad \texttt{xacro.process\_file()} para interpretar el modelo XML parametrizado. Posteriormente, aplica expresiones regulares para remover los comentarios XML redundantes con el fin de prevenir errores en el parser de ROS 2 y evitar inconsistencias en el plugin de Gazebo.
    \item \textbf{Gestión de Rutas de Modelos de Gazebo:} Actualiza dinámicamente la variable de entorno \texttt{GAZEBO\_MODEL\_PATH} para incluir el directorio local de mallas STL del brazo, garantizando la carga correcta de las geometrías de visualización en Gazebo Classic.
    \item \textbf{Secuenciación de Nodos mediante Manejo de Eventos:} Para evitar condiciones de carrera donde los controladores articulares intentan enlazarse antes de que el robot exista físicamente en la física del simulador, el script utiliza manejadores de eventos \texttt{RegisterEventHandler} y \texttt{OnProcessExit}. Esto fuerza que el controlador de posición de las articulaciones (\texttt{arm\_controller}) se lance únicamente después de que el robot haya sido instanciado por el nodo \texttt{spawn\_entity}.
\end{itemize}

\subsection{Modelo Descriptor de la Estructura y Actuadores (arm.urdf.xacro)}
El diseño estructural, los límites de movimiento y la configuración de hardware de control del gemelo virtual se definen jerárquicamente en un archivo descriptor Xacro, presentado en el Código~\ref{lst:urdf_xacro} en el Apéndice~\ref{ap:urdf_xacro}.
Este descriptor se estructura a partir de los siguientes elementos clave:
\begin{itemize}
    \item \textbf{Geometría de Eslabones y Mallas STL:} Vincula directamente los archivos STL exportados de CAD (\texttt{base.stl}, \texttt{link1.stl}, etc.) escalados a metros (factor $0.001$), definiendo la apariencia visual del robot en el simulador.
    \item \textbf{Límites y Dinámica de Articulaciones:} Modela los límites físicos angulares en radianes equivalentes a los límites de los servomotores físicos del prototipo. Adicionalmente, incluye parámetros dinámicos de fricción y amortiguamiento (\texttt{friction} y \texttt{damping}) para modelar el rozamiento de las articulaciones en Gazebo.
    \item \textbf{Integración con ros2\_control:} Declara el elemento \texttt{<ros2\_control>} que mapea las interfaces de comando y de estado (posiciones articulares y velocidades) del resolvedor de física de Gazebo Classic (\texttt{gazebo\_ros2\_control/GazeboSystem}), permitiendo la inyección directa de señales desde el puente de comunicación HTTP. Esta declaración se complementa en la arquitectura de ROS 2 con el archivo de configuración \texttt{controllers.yaml}, el cual especifica la tasa de actualización de los bucles de control a $100\text{ Hz}$ y define un controlador síncrono del tipo \texttt{JointGroupPositionController} asociado a las tres articulaciones activas del robot.
\end{itemize}

\subsection{Firmware Embebido del Microcontrolador Físico (main.cpp)}
Para el control directo y la coordinación de los actuadores del prototipo físico, se desarrolló un firmware embebido en C++ ejecutado sobre el microcontrolador ESP32. Su implementación completa se detalla en el Código~\ref{lst:main_cpp} en el Apéndice~\ref{ap:main_cpp}. Las principales funcionalidades de control, decodificación y seguridad implementadas se describen a continuación:
\begin{itemize}
    \item \textbf{Configuración de Periféricos e Inicialización de Actuadores:} El firmware utiliza la biblioteca \texttt{ESP32Servo} reservando tres temporizadores de hardware a una frecuencia de control de $50\text{ Hz}$ para generar las señales de modulación por ancho de pulso (PWM) destinadas a los servomotores de la base (\texttt{GPIO 27}), hombro (\texttt{GPIO 14}) y codo (\texttt{GPIO 21}). Adicionalmente, el pin \texttt{GPIO 22} se define como una salida digital para la conmutación del emisor láser.
    \item \textbf{Decodificación Bidireccional y Parser de Tramas Duales:} El firmware en su bucle periódico `loop()` decodifica tramas provenientes de la interfaz serial UART a una tasa de $115200\text{ bps}$. El parser soporta dos modos de entrada dinámicos:
        \begin{enumerate}
            \item \textit{Modo Cartesiano (X:val,Y:val,Z:val):} El microcontrolador ejecuta localmente el modelo de cinemática inversa analítico codo-arriba. Si las coordenadas se envían en milímetros (valores absolutos $> 2.0$), el firmware las escala a metros de forma automática.
            \item \textit{Modo Directo de Juntas (J1:val,J2:val,J3:val,L:val):} La interfaz web envía directamente los ángulos articulares en grados sexagesimales junto con el estado del láser (`L:0` o `L:1`). El firmware los convierte a radianes y asocia el control de PWM de forma directa.
        \end{enumerate}
    \item \textbf{Conversión Articular y Mapeo PWM de Precisión:} La función \texttt{angleToMicroseconds()} toma el ángulo articular en radianes, valida y restringe su valor según los límites angulares permitidos (para evitar colisiones destructivas) y realiza el mapeo lineal al ancho de pulso:
        \begin{equation}
        t_{\mu\text{s}} = 1500 + \theta \cdot \frac{2000}{\pi}
        \end{equation}
        clampando el resultado estrictamente en la banda de seguridad de $[500, 2500]\,\mu\text{s}$.
    \item \textbf{Algoritmo de Movimiento Gradual Simultáneo (moveToTarget):} Para evitar picos severos de corriente instantánea debido a la inercia del manipulador (que activarían el circuito de protección OCP de la fuente ATX, apagando el ESP32), se programó un perfilador de movimiento gradual. La rutina \texttt{moveToTarget()} interpola linealmente el ancho de pulso de los tres servos en pasos simultáneos máximos de $15\,\mu\text{s}$ ($\approx 1.35^\circ$) espaciados por retardos temporales fijos de $15\text{ ms}$, eliminando los transitorios de corriente dañinos.
    \textbf{Watchdog por Software y Parada de Emergencia:} Para prevenir incendios o marcas incidentales en la pieza de trabajo por fallos de comunicación en el lazo de control, se implementó un temporizador de watchdog por software. Si transcurren más de $1000\text{ ms}$ sin la llegada de comandos válidos, el láser se apaga automáticamente. Asimismo, ante la trama `ESTOP` o `EMERGENCY`, la rutina \texttt{triggerEmergency()} realiza el apagado inmediato del emisor láser y desasocia (`detach()`) las señales PWM para liberar la tensión en los servomotores.
\end{itemize}

\section{Selección de Actuadores y Sensores}
Para garantizar el éxito de la implementación física y su congruencia con el entorno de simulación, se detalla la selección de componentes de hardware:


\subsection{Actuadores}
La arquitectura cinemática de 3 GDL resulta idónea para este caso de estudio; dado que la herramienta es un haz láser unidireccional colineal con el eje de aproximación, y el objetivo es el corte y grabado sobre superficies cilíndricas, el control del posicionamiento cartesiano en los tres ejes ($X, Y, Z$) es crítico para compensar la curvatura de la pieza y mantener la distancia focal constante del haz. La omisión del control de orientación redundante (pitch/roll) disminuye drásticamente el torque estático requerido en las articulaciones proximales (base y hombro), lo que mitiga las deflexiones estructurales y maximiza la rigidez y repetibilidad del sistema. El diseño se complementa ubicando estratégicamente actuadores de baja masa en los eslabones distales para minimizar el tensor de inercia del mecanismo.

\begin{itemize}
    \item \textbf{Actuador de rotación principal (Base):} Se implementó un servomotor de alto torque y engranajes metálicos (MG996R) en la base para accionar el giro del brazo a la izquierda y derecha. Este actuador soporta las cargas dinámicas y el momento de inercia de toda la estructura móvil.
    \item \textbf{Actuadores de elevación (Hombro y Codo):} Se utilizó un servomotor de alto torque MG996R para el hombro (articulación pegada a la base que hace elevar el brazo) para soportar el peso y los esfuerzos de flexión de los eslabones, y un servomotor de engranajes metálicos MG90S en la articulación del codo para controlar la elevación distal.
    \item \textbf{Efector final (Módulo Láser de estado sólido):} Consiste en un diodo láser de baja potencia con lógica transistor-transistor (TTL) de 5V, el cual es conmutado como un nivel lógico de entrada/salida de propósito general (GPIO) o vía PWM desde el ESP32. Esto permite una activación síncrona y de baja latencia acoplada al perfil cinemático de la trayectoria, emulando la dinámica de interpolación de un proceso industrial de corte láser CNC.
\end{itemize}

\subsection{Sensores}
\begin{itemize}
    \item \textbf{Potenciómetros internos:} Los servomotores ya incluyen sensores de posición (potenciómetros) internamente. Esto mantiene el diseño mecánico limpio ya que no se requiere acoplar encoders ópticos externos para leer los ángulos de las articulaciones, eliminando la necesidad de cableado para sensores externos de posición o corriente.
    \item \textbf{Cámara física de monitoreo:} Se integra una cámara USB externa para la captura y monitoreo del proceso de guiado en tiempo real. Físicamente, el lente de la cámara se ubica fijamente a una distancia de $15\text{ cm}$ ($150\text{ mm}$) desde el origen del sistema de referencia de la base $\{0\}$ a lo largo de su eje longitudinal $X_0$, y a una altura de $2.5\text{ cm}$ ($25\text{ mm}$) a lo largo del eje vertical $Z_0$. Esta colocación rígida permite obtener una visualización cenital despejada de la superficie cilíndrica a mecanizar.
\end{itemize}

\section{Aplicación Industrial}
A diferencia de los pantógrafos y cortadoras láser cartesianas convencionales, los cuales están limitados a trazar trayectorias coplanares bidimensionales ($2\text{D}$) en láminas planas, la configuración antropomórfica de 3 GDL permite posicionar la herramienta en un espacio tridimensional ($X, Y, Z$). Esta característica habilita la aplicación del robot en procesos industriales de corte y grabado sobre superficies irregulares y no coplanares, tales como el perfilado de cuerpos curvados y el calado de piezas cilíndricas.

En la industria de manufactura mecánica, el procesamiento de piezas no planas requiere realizar cortes y grabados con perfiles tridimensionales complejos (por ejemplo, intersecciones de geometrías cilíndricas o marcas en piezas curvas). Al colocar un haz láser en el efector final del robot, es posible realizar este proceso sin contacto mecánico directo. A partir del modelo de la superficie cilíndrica de una pieza de radio $R_{tubo}$ colocada de forma horizontal a lo largo del eje $Y_0$ a una distancia $x_{tubo}$ y a una altura de desfase $z_{tubo}$, la coordenada vertical de corte $z_E$ se calcula dinámicamente en función de la posición radial $x_E$:
\begin{equation}
z_E = z_{tubo} + \sqrt{R_{tubo}^2 - (x_E - x_{tubo})^2}
\label{eq:tubo}
\end{equation}
El resolvedor de cinemática inversa desarrollado en \eqref{eq:ik_theta1}-\eqref{eq:ik_theta2} calcula de manera instantánea las posiciones articulares $(\theta_1, \theta_2, \theta_3)$ para que el láser siga esta trayectoria no planar, manteniendo la distancia focal constante respecto a la pared de la pieza. Esto demuestra el valor industrial del manipulador propuesto frente a las soluciones cartesianas convencionales de bajo costo, ampliando el alcance de automatización hacia geometrías complejas no convencionales.

function solveIK(x, y, z, customL2) {
  const targetX = parseFloat(x);
  const targetY = parseFloat(y);
  const targetZ = parseFloat(z);
  
  const currentL2 = (customL2 !== undefined) ? customL2 : L2;

  if (isNaN(targetX) || isNaN(targetY) || isNaN(targetZ)) {
    return { error: 'VALORES_INVALIDOS', msg: 'Ingresa valores numericos validos.' };
  }

  let r = Math.sqrt(targetX * targetX + targetY * targetY);
  if (r < Math.abs(d4)) {
    r = Math.abs(d4);
  }
  const Rp = Math.sqrt(r * r - d4 * d4);
  const theta1 = (targetX === 0 && targetY === 0) ? -Math.PI / 2 : Math.atan2(targetY, targetX) - Math.atan2(-d4, Rp);
  const j1 = theta1 * 180 / Math.PI;

  if (j1 < jointsConfig[1].min || j1 > jointsConfig[1].max) {
    return { error: 'FUERA DE ALCANCE', msg: 'Rotacion base J1 fuera de limites (-165 a 165).' };
  }

  const xc = Rp - a2;
  const zc = targetZ - (d1 + d2);

  const psi_numerator = xc * xc + zc * zc - L1 * L1 - currentL2 * currentL2;
  const psi_denominator = 2.0 * L1 * currentL2;
  let psi = psi_numerator / psi_denominator;

  if (psi > 1.0 && psi <= 1.005) {
    psi = 1.0;
  } else if (psi < -1.0 && psi >= -1.005) {
    psi = -1.0;
  }

  if (psi < -1.0 || psi > 1.0) {
    return { error: 'FUERA DE ALCANCE', msg: 'Coordenadas fuera del alcance del brazo.' };
  }

  const solutions = [-1, 1];
  for (let s of solutions) {
    const sinTheta3_star = s * Math.sqrt(1.0 - psi * psi);
    const theta3_star = Math.atan2(sinTheta3_star, psi);

    const theta2_star = Math.atan2(zc, xc) - Math.atan2(currentL2 * sinTheta3_star, L1 + currentL2 * psi);

    const theta2 = theta2_star;
    const theta3 = theta3_star;

    const j2 = theta2 * 180 / Math.PI;
    const j3 = theta3 * 180 / Math.PI;

    if (j2 >= jointsConfig[2].min && j2 <= jointsConfig[2].max &&
        j3 >= jointsConfig[3].min && j3 <= jointsConfig[3].max) {
      return { j1, j2, j3 };
    }
  }

  return { error: 'FUERA DE ALCANCE', msg: 'Posicion cinematicamente inalcanzable por limites de articulacion.' };
}

\section{Código del Generador de Trayectorias de Simulación (trajectory\_generator.py)}
\label{ap:traj_py}
\begin{lstlisting}[language=Python,caption={\small Generación de perfiles S-curve por interpolación cosenoidal y control de keyframes (trajectory\_generator.py).},label={lst:traj_py}]
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64MultiArray
import time
import math

class TrajectoryGenerator(Node):
    def __init__(self):
        """
        Inicializa el nodo de ROS 2, configura el publicador de comandos de control,
        define los keyframes de la secuencia de corte industrial y arranca el temporizador de interpolacion.
        """
        super().__init__('trajectory_generator')
        self.publisher_ = self.create_publisher(Float64MultiArray, '/arm_controller/commands', 10)

        self.rate = 50.0
        self.timer = self.create_timer(1.0 / self.rate, self.timer_callback)

        self.keyframes = [
            {"pose": [0.0, 0.0, 0.0], "time": 3.0},
            {"pose": [-0.6, 0.4, -0.4], "time": 3.0},
            {"pose": [0.6, 0.4, -0.4], "time": 4.0},
            {"pose": [0.6, 0.6, -0.7], "time": 2.0},
            {"pose": [-0.6, 0.6, -0.7], "time": 4.0},
            {"pose": [0.0, 0.0, 0.0], "time": 3.0}
        ]

        self.current_keyframe_idx = 0
        self.step_counter = 0
        self.total_steps_for_transition = 0
        self.start_pose = [0.0, 0.0, 0.0]
        self.target_pose = self.keyframes[0]["pose"]

        self.get_logger().info("Nodo de trayectoria inicializado. Iniciando ciclo de corte...")
        self.prepare_next_transition()

    def prepare_next_transition(self):
        """
        Prepara los parametros cinematicos y de interpolacion para la transicion hacia el
        siguiente keyframe de la secuencia, incrementando el indice de trayectoria.
        """
        self.start_pose = list(self.target_pose)
        keyframe = self.keyframes[self.current_keyframe_idx]
        self.target_pose = keyframe["pose"]
        duration = keyframe["time"]

        self.total_steps_for_transition = int(duration * self.rate)
        self.step_counter = 0

        self.get_logger().info(
            f"Transicionando a Keyframe {self.current_keyframe_idx}: {self.target_pose} en {duration}s"
        )

        self.current_keyframe_idx = (self.current_keyframe_idx + 1) % len(self.keyframes)

    def timer_callback(self):
        """
        Ejecuta periodicamente la interpolacion cosenoidal (S-curve) entre poses conjuntas
        sucesivas y publica el vector de comandos correspondiente a la tasa del bucle.
        """
        if self.step_counter >= self.total_steps_for_transition:
            self.prepare_next_transition()

        t = float(self.step_counter) / float(self.total_steps_for_transition)
        smooth_t = (1.0 - math.cos(t * math.pi)) / 2.0

        current_command = []
        for start, target in zip(self.start_pose, self.target_pose):
            val = start + (target - start) * smooth_t
            current_command.append(val)

        msg = Float64MultiArray()
        msg.data = current_command
        self.publisher_.publish(msg)

        self.step_counter += 1


def main(args=None):
    """
    Funcion de entrada que inicializa el entorno de ROS 2, instancia el generador de trayectoria,
    mantiene el ciclo de ejecucion activo y maneja el apagado limpio del nodo.
    """
    rclpy.init(args=args)
    node = TrajectoryGenerator()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        node.get_logger().info("Generador de trayectoria detenido por el usuario.")
    finally:
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
\end{lstlisting}

\section{Código del Firmware de Control de Bajo Nivel y Láser en el ESP32 (main.cpp)}
\label{ap:main_cpp}
\begin{lstlisting}[language=C++,caption={\small Firmware embebido en C++ para control de servomotores y conmutación láser en el ESP32 (main.cpp).},label={lst:main_cpp}]
#include <Arduino.h>
#include <ESP32Servo.h>
#include <math.h>

#define SERVO_BASE_PIN     27
#define SERVO_SHOULDER_PIN 14
#define SERVO_ELBOW_PIN    21
#define LASER_PIN          22

// Constantes fisicas del brazo (metros)
const float L0 = 0.096f;
const float L1 = 0.146f;
const float L2 = 0.161f;

// Limites de las articulaciones (radianes)
const float MIN_THETA1 = -1.5708f; // -90 grados
const float MAX_THETA1 =  1.5708f; // +90 grados
const float MIN_THETA2 = -0.1745f; // -10 grados
const float MAX_THETA2 =  1.5708f; // +90 grados
const float MIN_THETA3 = -2.0944f; // -120 grados
const float MAX_THETA3 =  0.1745f; // +10 grados

const unsigned long SERIAL_TIMEOUT_MS = 1000;

Servo servoBase;
Servo servoShoulder;
Servo servoElbow;

// Variables de estado (microsegundos correspondientes a la posicion del servo)
int currentBaseUs = 1500;
int currentShoulderUs = 1500;
int currentElbowUs = 1500;

unsigned long lastPacketTime = 0;
bool isEmergency = false;

/*
 * Convierte un angulo articular en radianes al correspondiente ancho de pulso PWM en microsegundos,
 * limitando el resultado entre los margenes fisicos y de seguridad del servomotor.
 */
int angleToMicroseconds(float angle_rad, float min_rad, float max_rad) {
  float clamped = constrain(angle_rad, min_rad, max_rad);
  float us = 1500.0f + clamped * (2000.0f / PI);
  return constrain((int)us, 500, 2500);
}

/*
 * Resuelve analiticamente el modelo cinematico inverso para un brazo de 3 GDL bajo
 * la configuracion geometrica de codo arriba a partir de una posicion cartesiana (x, y, z).
 */
bool solveInverseKinematics(float x, float y, float z, float &t1, float &t2, float &t3) {
  t1 = atan2(y, x);

  float r = sqrt(x * x + y * y);
  float z_prime = z - L0;

  float psi_numerator = x * x + y * y + z_prime * z_prime - L1 * L1 - L2 * L2;
  float psi_denominator = 2.0f * L1 * L2;
  float psi = psi_numerator / psi_denominator;

  if (psi < -1.0f || psi > 1.0f) {
    return false;
  }

  t3 = atan2(-sqrt(1.0f - psi * psi), psi);

  t2 = atan2(z_prime, r) - atan2(L2 * sin(t3), L1 + L2 * cos(t3));

  return true;
}

/*
 * Activa de forma inmediata el estado de emergencia, apaga el emisor laser de corte
 * y desacopla la senal de los servomotores para liberar la tension de la estructura.
 */
void triggerEmergency(const char* reason) {
  isEmergency = true;
  digitalWrite(LASER_PIN, LOW);
  
  servoBase.detach();
  servoShoulder.detach();
  servoElbow.detach();
  
  Serial.print("\n=== PARADA DE EMERGENCIA ACTIVA ===\nMotivo: ");
  Serial.println(reason);
  Serial.println("Reinicie el ESP32 para reestablecer el sistema.");
}

/*
 * Mueve todos los servos gradualmente en pasos simultaneos para evitar picos de corriente
 * bruscos que provoquen el apagado o proteccion de la fuente de alimentacion ATX.
 */
void moveToTarget(int targetBaseUs, int targetShoulderUs, int targetElbowUs, int stepUs = 15, int stepDelay = 15) {
  bool baseMoving = true;
  bool shoulderMoving = true;
  bool elbowMoving = true;
  
  while (baseMoving || shoulderMoving || elbowMoving) {
    if (isEmergency) {
      return;
    }
    
    // Alimentar el temporizador del watchdog de seguridad durante el recorrido
    lastPacketTime = millis();

    baseMoving = (currentBaseUs != targetBaseUs);
    shoulderMoving = (currentShoulderUs != targetShoulderUs);
    elbowMoving = (currentElbowUs != targetElbowUs);
    
    if (baseMoving) {
      if (abs(targetBaseUs - currentBaseUs) <= stepUs) {
        currentBaseUs = targetBaseUs;
      } else {
        currentBaseUs += (targetBaseUs > currentBaseUs) ? stepUs : -stepUs;
      }
      servoBase.writeMicroseconds(currentBaseUs);
    }
    
    if (shoulderMoving) {
      if (abs(targetShoulderUs - currentShoulderUs) <= stepUs) {
        currentShoulderUs = targetShoulderUs;
      } else {
        currentShoulderUs += (targetShoulderUs > currentShoulderUs) ? stepUs : -stepUs;
      }
      servoShoulder.writeMicroseconds(currentShoulderUs);
    }
    
    if (elbowMoving) {
      if (abs(targetElbowUs - currentElbowUs) <= stepUs) {
        currentElbowUs = targetElbowUs;
      } else {
        currentElbowUs += (targetElbowUs > currentElbowUs) ? stepUs : -stepUs;
      }
      servoElbow.writeMicroseconds(currentElbowUs);
    }
    
    if (baseMoving || shoulderMoving || elbowMoving) {
      delay(stepDelay);
    }
  }
}

void setup() {
  Serial.begin(115200);
  delay(500);
  Serial.println("\n=== ESP32 3-GDL Laser Arm Controller (Gradual Move) ===");

  pinMode(LASER_PIN, OUTPUT);
  digitalWrite(LASER_PIN, LOW);

  ESP32PWM::allocateTimer(0);
  ESP32PWM::allocateTimer(1);
  ESP32PWM::allocateTimer(2);
  
  servoBase.setPeriodHertz(50);
  servoShoulder.setPeriodHertz(50);
  servoElbow.setPeriodHertz(50);

  // Inicializar servos y asociar pines
  servoBase.attach(SERVO_BASE_PIN, 500, 2500);
  servoShoulder.attach(SERVO_SHOULDER_PIN, 500, 2500);
  servoElbow.attach(SERVO_ELBOW_PIN, 500, 2500);

  // Establecer posicion central por defecto al encender
  servoBase.writeMicroseconds(currentBaseUs);
  servoShoulder.writeMicroseconds(currentShoulderUs);
  servoElbow.writeMicroseconds(currentElbowUs);

  lastPacketTime = millis();
  Serial.println("Sistema listo. Esperando comandos seriales (ej: X:0.2,Y:0.0,Z:0.25 o X:120,Y:0,Z:100)...");
}

void loop() {
  if (isEmergency) {
    digitalWrite(LASER_PIN, LOW);
    delay(100);
    return;
  }

  // Watchdog de seguridad: apaga el laser si se pierde la comunicacion serial
  if (millis() - lastPacketTime > SERIAL_TIMEOUT_MS) {
    digitalWrite(LASER_PIN, LOW);
  }

  if (Serial.available() > 0) {
    String line = Serial.readStringUntil('\n');
    line.trim();

    if (line.length() > 0) {
      // Comando manual para parada de emergencia
      if (line.equalsIgnoreCase("ESTOP") || line.equalsIgnoreCase("EMERGENCY")) {
        triggerEmergency("Comando manual recibido");
        return;
      }

      int idxJ1 = line.indexOf("J1:");
      int idxJ2 = line.indexOf("J2:");
      int idxJ3 = line.indexOf("J3:");
      int idxL  = line.indexOf(",L:");

      int idxX = line.indexOf("X:");
      int idxY = line.indexOf("Y:");
      int idxZ = line.indexOf("Z:");

      if (idxJ1 != -1 && idxJ2 != -1 && idxJ3 != -1) {
        int endJ1 = line.indexOf(',', idxJ1);
        int endJ2 = line.indexOf(',', idxJ2);
        int endJ3 = (idxL != -1) ? idxL : line.length();

        String j1Str = line.substring(idxJ1 + 3, endJ1 != -1 ? endJ1 : line.length());
        String j2Str = line.substring(idxJ2 + 3, endJ2 != -1 ? endJ2 : line.length());
        String j3Str = line.substring(idxJ3 + 3, endJ3 != -1 ? endJ3 : line.length());

        float j1_deg = j1Str.toFloat();
        float j2_deg = j2Str.toFloat();
        float j3_deg = j3Str.toFloat();

        bool laserVal = false;
        if (idxL != -1) {
          String lStr = line.substring(idxL + 3);
          laserVal = (lStr.toInt() > 0);
        }

        float theta1 = j1_deg * PI / 180.0f;
        float theta2 = j2_deg * PI / 180.0f;
        float theta3 = j3_deg * PI / 180.0f;

        int base_us = angleToMicroseconds(theta1, MIN_THETA1, MAX_THETA1);
        int shoulder_us = angleToMicroseconds(theta2, MIN_THETA2, MAX_THETA2);
        int elbow_us = angleToMicroseconds(theta3, MIN_THETA3, MAX_THETA3);

        lastPacketTime = millis();
        if (laserVal) {
          digitalWrite(LASER_PIN, HIGH);
        } else {
          digitalWrite(LASER_PIN, LOW);
        }

        moveToTarget(base_us, shoulder_us, elbow_us);

        Serial.print("OK | Joints set: J1=");
        Serial.print(j1_deg, 1);
        Serial.print(" J2=");
        Serial.print(j2_deg, 1);
        Serial.print(" J3=");
        Serial.print(j3_deg, 1);
        Serial.print(" | Laser=");
        Serial.println(laserVal ? "ON" : "OFF");
      } else if (idxX != -1 && idxY != -1 && idxZ != -1) {
        int endX = line.indexOf(',', idxX);
        int endY = line.indexOf(',', idxY);
        int endZ = line.length();

        String xStr = line.substring(idxX + 2, endX != -1 ? endX : line.length());
        String yStr = line.substring(idxY + 2, endY != -1 ? endY : line.length());
        String zStr = line.substring(idxZ + 2, endZ);

        float raw_x = xStr.toFloat();
        float raw_y = yStr.toFloat();
        float raw_z = zStr.toFloat();

        float scale = 1.0f;
        if (abs(raw_x) > 2.0f || abs(raw_y) > 2.0f || abs(raw_z) > 2.0f) {
          scale = 0.001f;
        }

        float x = raw_x * scale;
        float y = raw_y * scale;
        float z = raw_z * scale;

        float theta1 = 0.0f, theta2 = 0.0f, theta3 = 0.0f;
        if (solveInverseKinematics(x, y, z, theta1, theta2, theta3)) {
          lastPacketTime = millis();
          digitalWrite(LASER_PIN, HIGH);

          int base_us = angleToMicroseconds(theta1, MIN_THETA1, MAX_THETA1);
          int shoulder_us = angleToMicroseconds(theta2, MIN_THETA2, MAX_THETA2);
          int elbow_us = angleToMicroseconds(theta3, MIN_THETA3, MAX_THETA3);

          // Movimiento de servos en pasos graduales suaves
          moveToTarget(base_us, shoulder_us, elbow_us);

          Serial.print("OK | Target: X=");
          Serial.print(x, 4);
          Serial.print(" Y=");
          Serial.print(y, 4);
          Serial.print(" Z=");
          Serial.print(z, 4);
          Serial.print(" | Joints: T1=");
          Serial.print(theta1 * 180.0f / PI, 1);
          Serial.print(" T2=");
          Serial.print(theta2 * 180.0f / PI, 1);
          Serial.print(" T3=");
          Serial.println(theta3 * 180.0f / PI, 1);
        } else {
          Serial.println("ERR: Posicion cartesiana fuera del area de alcance.");
        }
      } else {
        Serial.println("WARN: Formato invalido. Use 'X:val,Y:val,Z:val'");
      }
    }
  }
}

\section{Código del Algoritmo de Adelgazamiento Zhang-Suen (web\_bridge.py)}
\label{ap:zhang_py}
\begin{lstlisting}[language=Python,caption={\small Algoritmo de esqueletización vectorizada de Zhang-Suen (web\_bridge.py).},label={lst:zhang_py}]
def zhang_suen_thinning(img):
    import numpy as np
    im = (img > 0).astype(np.uint8)
    im = np.pad(im, 1, mode='constant', constant_values=0)
    
    while True:
        # Paso 1
        p2 = im[:-2, 1:-1]
        p3 = im[:-2, 2:]
        p4 = im[1:-1, 2:]
        p5 = im[2:, 2:]
        p6 = im[2:, 1:-1]
        p7 = im[2:, :-2]
        p8 = im[1:-1, :-2]
        p9 = im[:-2, :-2]
        
        B = p2 + p3 + p4 + p5 + p6 + p7 + p8 + p9
        
        A = ((p2 == 0) & (p3 == 1)).astype(np.uint8) + \
            ((p3 == 0) & (p4 == 1)).astype(np.uint8) + \
            ((p4 == 0) & (p5 == 1)).astype(np.uint8) + \
            ((p5 == 0) & (p6 == 1)).astype(np.uint8) + \
            ((p6 == 0) & (p7 == 1)).astype(np.uint8) + \
            ((p7 == 0) & (p8 == 1)).astype(np.uint8) + \
            ((p8 == 0) & (p9 == 1)).astype(np.uint8) + \
            ((p9 == 0) & (p2 == 1)).astype(np.uint8)
            
        cond1 = (B >= 2) & (B <= 6) & (A == 1) & (p2 * p4 * p6 == 0) & (p4 * p6 * p8 == 0)
        inner = im[1:-1, 1:-1]
        to_delete_1 = (inner == 1) & cond1
        
        im[1:-1, 1:-1] = np.where(to_delete_1, 0, inner)
        
        # Paso 2
        p2 = im[:-2, 1:-1]
        p3 = im[:-2, 2:]
        p4 = im[1:-1, 2:]
        p5 = im[2:, 2:]
        p6 = im[2:, 1:-1]
        p7 = im[2:, :-2]
        p8 = im[1:-1, :-2]
        p9 = im[:-2, :-2]
        
        B = p2 + p3 + p4 + p5 + p6 + p7 + p8 + p9
        A = ((p2 == 0) & (p3 == 1)).astype(np.uint8) + \
            ((p3 == 0) & (p4 == 1)).astype(np.uint8) + \
            ((p4 == 0) & (p5 == 1)).astype(np.uint8) + \
            ((p5 == 0) & (p6 == 1)).astype(np.uint8) + \
            ((p6 == 0) & (p7 == 1)).astype(np.uint8) + \
            ((p7 == 0) & (p8 == 1)).astype(np.uint8) + \
            ((p8 == 0) & (p9 == 1)).astype(np.uint8) + \
            ((p9 == 0) & (p2 == 1)).astype(np.uint8)
            
        cond2 = (B >= 2) & (B <= 6) & (A == 1) & (p2 * p4 * p8 == 0) & (p2 * p6 * p8 == 0)
        inner = im[1:-1, 1:-1]
        to_delete_2 = (inner == 1) & cond2
        
        im[1:-1, 1:-1] = np.where(to_delete_2, 0, inner)
        
        if not np.any(to_delete_1) and not np.any(to_delete_2):
            break
            
    return (im[1:-1, 1:-1] * 255).astype(np.uint8)

\section{Código de Verificación Cinemática y DH (test\_kinematics.py)}

import numpy as np

# Constantes del robot
d1 = 60.0
d2 = 36.0
a2 = 15.0
a3 = 146.0
a4 = 161.0
d4 = -7.0

phi2 = 1.030041
phi3 = -0.191392

def dh_matrix(theta, d, a, alpha):
    alpha_rad = np.radians(alpha) if isinstance(alpha, (int, float)) else alpha
    return np.array([
        [np.cos(theta), -np.sin(theta)*np.cos(alpha_rad),  np.sin(theta)*np.sin(alpha_rad), a*np.cos(theta)],
        [np.sin(theta),  np.cos(theta)*np.cos(alpha_rad), -np.cos(theta)*np.sin(alpha_rad), a*np.sin(theta)],
        [0,              np.sin(alpha_rad),               np.cos(alpha_rad),              d],
        [0,              0,                               0,                              1]
    ])

def fk_dh(theta1, theta2, theta3):
    theta2_star = theta2 + phi2
    theta3_star = theta3 + phi3 - phi2
    
    T1 = dh_matrix(theta1, d1 + d2, a2, 90)
    T2 = dh_matrix(theta2_star, 0, a3, 0)
    T3 = dh_matrix(theta3_star, d4, a4, 0)
    
    T = T1 @ T2 @ T3
    return T

def fk_analytical(theta1, theta2, theta3):
    theta2_star = theta2 + phi2
    theta3_star = theta3 + phi3 - phi2
    
    x_plane = a2 + a3 * np.cos(theta2_star) + a4 * np.cos(theta2_star + theta3_star)
    z_plane = d1 + d2 + a3 * np.sin(theta2_star) + a4 * np.sin(theta2_star + theta3_star)
    
    x = x_plane * np.cos(theta1) + d4 * np.sin(theta1)
    y = x_plane * np.sin(theta1) - d4 * np.cos(theta1)
    z = z_plane
    return np.array([x, y, z])

# Probar con angulos cero
t1, t2, t3 = 0.0, 0.0, 0.0
T_dh = fk_dh(t1, t2, t3)
pos_dh = T_dh[:3, 3]
pos_analyt = fk_analytical(t1, t2, t3)

print("D-H End Effector Position (3 matrices):")
print(pos_dh)
print("\nAnalytical End Effector Position:")
print(pos_analyt)

                x_axis = R[:, 0]

                elif abs(angle_deg) > 0.1:
                    print(f"  [WARN] ADVERTENCIA: El eje X no es paralelo al eje X horizontal (Angulo = {angle_deg:.4f} deg)")
                    all_parallel = False
                else:
                    print("  [OK] ALINEACION PERFECTA (eje X paralelo y horizontal)")

        print("\n" + "="*70)
        if all_parallel:

        return np.array([

            [2*(x*y + w*z), 1 - 2*(x**2 + z**2), 2*(y*z - w*x)],
            [2*(x*z - w*y), 2*(y*z + w*x), 1 - 2*(x**2 + y**2)]
        ])

def rpy_to_matrix(r, p, y):
    cr, sr = math.cos(r), math.sin(r)
    cp, sp = math.cos(p), math.sin(p)
    cy, sy = math.cos(y), math.sin(y)
    
    Rx = np.array([[1, 0, 0], [0, cr, -sr], [0, sr, cr]])
    Ry = np.array([[cp, 0, sp], [0, 1, 0], [-sp, 0, cp]])
    Rz = np.array([[cy, -sy, 0], [sy, cy, 0], [0, 0, 1]])
